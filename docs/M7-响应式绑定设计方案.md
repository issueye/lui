# lui M7 设计方案：响应式绑定（参照 Vue 3 对 XML + CSS + TS 的分析与调整）

> 状态：设计已确认（2026-09-12）。参照 Vue 3（Composition API + 模板声明式）的精髓，
> 在"零构建、零第三方依赖、自研 TS 子集解释器"约束下做适配性调整。
> 实施进度：**M7-1（响应式内核 + 声明式绑定）已完成**。

---

## 1. 对照分析：当前三层 vs Vue 3

| 层 | 现状 | Vue 3 的做法 | 差距结论 |
| --- | --- | --- | --- |
| **XML（结构）** | 纯静态结构 + 字符串事件名（`onclick="OnAdd"`）。数据 → UI 靠脚本命令式操作 DOM（`document.find(...).text := ...`） | 模板即声明：插值 `{{ }}`、`v-bind`(`:`)、`v-on`(`@`)、`v-if`、`v-for`、`v-model`；**UI = f(state)** | **核心差距**：无任何声明式数据绑定；无条件/列表渲染；无双向绑定 |
| **CSS（样式）** | 按页独立样式表 + 类/ID 选择器 + 伪类状态机 + transition | scoped style；`:class` 动态切换 | **基本达标**：每页独立样式表 ≈ scoped（天然隔离）；状态样式切换只差一个 `:class` 绑定。不引入 scoped 编译 |
| **TS（逻辑）** | 命令式 DOM 操作；状态散落全局变量；UI 更新人肉调用 `UpdateXxx()` | Composition API：`reactive/ref` 状态、`computed` 派生、`watch` 副作用、生命周期；**逻辑只改状态、不碰 DOM** | **核心差距**：无响应式状态与派生；逻辑与 DOM 更新耦合 |

**架构同构点（应保留）**：模板/样式/逻辑三文件按页共置（≈ SFC 的三段式）、零构建、
事件双来源（宿主 RTTI → 脚本）、声明式 CSS。这些与 Vue SFC 的设计取向一致，不需要改。

**要补的一环**：把"数据驱动"补上——**响应式状态 + XML 声明式绑定**，让
"写状态 → UI 自动更新"成为默认路径；命令式 DOM API 降级为逃生舱（与 Vue 中直接操作 DOM 的地位一致）。

## 2. 调整决策（ADR 19–21）

### ADR 19 —— 响应式实现：绑定集 + 批量脏检查（非 Proxy 依赖追踪）

| 方案 | 评价 |
| --- | --- |
| Vue 3 式 Proxy + 精细依赖追踪 | 解释器的对象是属性表，无 Proxy/访问器；引入依赖收集需改每一处属性读——成本远超收益 |
| **绑定集静态登记 + flush 时全量重求值（选定）** | 绑定集合来自 XML（静态、数量有界），重求值成本可控；实现简单、行为可预测；代价：与依赖追踪相比有少量无效重算（绑定数级别，可接受） |

与 Vue 1/Angular 1 的 digest 同族，但绑定集合是静态声明的，不做动态指令扫描。

### ADR 20 —— 模板：XML 直接解释（保留零构建）

Vue 3 把模板编译成渲染函数（构建期优化）；lui 保持**零构建**，XML 即模板、运行期解释。
绑定表达式由**同一个 TS 子集解释器**求值（同一语言、同一指令预算、同一错误路由），
表达式 AST 按源文缓存（编译一次）。

### ADR 21 —— 更新调度：安全点批量刷新（对齐 Vue 的 nextTick 批处理）

事件处理器/定时器/Promise 里连续多次写状态 → 只置脏；**安全点**（事件结束 / Tick /
排水之后）统一刷新一次绑定。语义与 Vue 的异步批处理一致：DOM 不会在同一切片内反复重算。

### 语法对齐表

| Vue 3 | lui M7 | 说明 |
| --- | --- | --- |
| `{{ msg }}` 插值 | `text="共 {{state.count}} 条"`（属性内插值） | lui 的文本在 text 属性中 |
| `:text="expr"` / `v-bind` | `:text="expr"`、`:class`、`:disabled`、`:show` | `:class` 为**追加**语义；`:show` 用内置 `.xui-hidden{display:none}` |
| `@click="fn"` / `v-on` | `@click="OnX"`（`onclick="OnX"` 继续兼容） | 复用事件双来源 |
| `v-if="expr"` | `v-if="expr"` | 假时摘除子树（保活），真时原位恢复 |
| `v-for="item in list"` | `v-for="item in state.items"`（容器级，非 keyed 重建） | 作用域注入 `item` 与 `index`；子树克隆重建 |
| `v-model="state.x"` | `v-model="state.x"`（input 节点） | 仅支持 `state.路径` 形式 |
| `reactive(obj)` | `reactive(obj)` | 顶层属性写入触发（v1 不追踪嵌套） |
| `computed(getter)` | `computed(fn)`，访问 `c.value` | 版本号缓存：每次响应式刷新后失效重算 |
| `watch(source, cb)` | `watch(fn, cb)`，flush 后比对（新/旧两个参数） | 值相等（严格相等）不触发 |
| `onMounted(fn)` | `onMount(fn)` | 文档就绪后按注册序调用一次（`Boot()` 保留兼容） |

### 刻意不做（v1）

- 精细依赖追踪 / `effect` 手动 API / `shallowRef` 等 —— ADR 19
- 组件化（props/emits/slots）—— 后续按需
- keyed v-for diff 复用 —— v1 全量重建子树
- scoped style 编译 —— 每页独立样式表已天然隔离

## 3. 运行形态（对齐 Vue 3 心智模型）

```
XML（模板）                TS（逻辑，Composition 风格）
<label text="共 {{state.count}} 条"/>
<button @click="OnAdd"/>          const state = reactive({ count: 0 });
                                  function OnAdd(e) { state.count += 1; }   ← 只写状态
        ↓ 响应式刷新（安全点批量，ADR 21）
DOM 自动更新（文本/类/可用性/显隐/结构），样式与布局按既有管线正确失效
```
