## 1. 对照分析：当前三层 vs Vue 3

| 层 | 现状 | Vue 3 的做法 | 差距结论 |
| --- | --- | --- | --- |
| **XML（结构）** | 纯静态结构 + 字符串事件名（`onclick="OnAdd"`）。数据 → UI 靠脚本命令式操作 DOM（`document.find(...).text := ...`） | 模板即声明：插值 `{{ }}`、`v-bind`(`:`)、`v-on`(`@`)、`v-if`、`v-for`、`v-model`；**UI = f(state)** | **核心差距**：无任何声明式数据绑定；无条件/列表渲染；无双向绑定 |
| **CSS（样式）** | 按页独立样式表 + 类/ID 选择器 + 伪类状态机 + transition | scoped style；`:class` 动态切换 | **基本达标**：每页独立样式表 ≈ scoped（天然隔离）；状态样式切换只差一个 `:class` 绑定。不引入 scoped 编译 |
| **TS（逻辑）** | 命令式 DOM 操作；状态散落全局变量；UI 更新人肉调用 `UpdateXxx()` | Composition API：`reactive/ref` 状态、`computed` 派生、`watch` 副作用、生命周期；**逻辑只改状态、不碰 DOM** | **核心差距**：无响应式状态与派生；逻辑与 DOM 更新耦合 |

**架构同构点（应保留）**：模板/样式/逻辑三文件按页共置（≈ SFC 的三段式）、零构建、
事件双来源（宿主 RTTI → 脚本）、声明式 CSS。这些与 Vue SFC 的设计取向一致，不需要改。

**要补的一环**：把"数据驱动"补上——**响应式状态 + XML 声明式绑定**，让
"写状态 → UI 自动更新"成为默认路径；命令式 DOM API 降级为逃生舱（与 Vue 中直接操作 DOM 的地位一致）。

## 2. 调整决策（ADR 19–21）

### ADR 19 —— 响应式实现：绑定集 + 批量脏检查（非 Proxy 依赖追踪）

| 方案 | 评价 |
| --- | --- |
| Vue 3 式 Proxy + 精细依赖追踪 | 解释器的对象是属性表，无 Proxy/访问器；引入依赖收集需改每一处属性读——成本远超收益 |
| **绑定集静态登记 + flush 时全量重求值（选定）** | 绑定集合来自 XML（静态、数量有界），重求值成本可控；实现简单、行为可预测；代价：与依赖追踪相比有少量无效重算（绑定数级别，可接受） |

与 Vue 1/Angular 1 的 digest 同族，但绑定集合是静态声明的，不做动态指令扫描。

### ADR 20 —— 模板：XML 直接解释（保留零构建）

Vue 3 把模板编译成渲染函数（构建期优化）；lui 保持**零构建**，XML 即模板、运行期解释。
绑定表达式由**同一个 TS 子集解释器**求值（同一语言、同一指令预算、同一错误路由），
表达式 AST 按源文缓存（编译一次）。

### ADR 21 —— 更新调度：安全点批量刷新（对齐 Vue 的 nextTick 批处理）

事件处理器/定时器/Promise 里连续多次写状态 → 只置脏；**安全点**（事件结束 / Tick /
排水之后）统一刷新一次绑定。语义与 Vue 的异步批处理一致：DOM 不会在同一切片内反复重算。

### 语法对齐表

| Vue 3 | lui M7 | 说明 |
| --- | --- | --- |
| `{{ msg }}` 插值 | `text="共 {{state.count}} 条"`（属性内插值） | lui 的文本在 text 属性中 |
| `:text="expr"` / `v-bind` | `:text="expr"`、`:class`、`:disabled`、`:show` | `:class` 为**追加**语义；`:show` 用内置 `.xui-hidden{display:none}` |
| `@click="fn"` / `v-on` | `@click="OnX"`（`onclick="OnX"` 继续兼容） | 复用事件双来源 |
| `v-if="expr"` | `v-if="expr"` | 假时摘除子树（保活），真时原位恢复 |
| `v-for="item in list"` | `v-for="item in state.items"` | 容器级；子节点 `x-key="expr"` 启用键控 diff（复用/移除/重排），无 `x-key` 按长度重建 |
| `v-model="state.x"` | `v-model="state.x"`（input 节点） | 仅支持 `state.路径` 形式 |
| `reactive(obj)` | `reactive(obj)` | 顶层属性写入触发（v1 不追踪嵌套） |
| `computed(getter)` | `computed(fn)`，访问 `c.value` | 版本号缓存：每次响应式刷新后失效重算 |
| `watch(source, cb)` | `watch(fn, cb)`，flush 后比对（新/旧两个参数） | 值相等（严格相等）不触发 |
| `onMounted(fn)` | `onMount(fn)` | 文档就绪后按注册序调用一次（`Boot()` 保留兼容） |

### 刻意不做（v1，部分已于 M7-2 兑现）

## 3. 运行形态（对齐 Vue 3 心智模型）

```
XML（模板）                TS（逻辑，Composition 风格）
<label text="共 {{state.count}} 条"/>
<button @click="OnAdd"/>          const state = reactive({ count: 0 });
                                  function OnAdd(e) { state.count += 1; }   ← 只写状态
        ↓ 响应式刷新（安全点批量，ADR 21）
DOM 自动更新（文本/类/可用性/显隐/结构），样式与布局按既有管线正确失效
```

## 7. M7-3 实施记录（追加，2026-09-12）

- **组件注册**：`component('name', { props: ['a', 'b'], template: '<panel>...</panel>' })`
  （绑定引擎构造时注册全局；模板为 XML 片段字符串，v1 要求单根）
- **实例化**：XML 扫描命中已注册标签 → 解析模板 → 建 props 容器（reactive，深度标记）→
  原位替换宿主标签 → 装配行为（ApplyNodeData）→ 以组件作用域（`props` 可见、父状态不可见）
  登记实例绑定；宿主 id/class 转移到实例根
- **props**：静态属性（字符串）即时赋值；`:prop="expr"` 登记bkProp 绑定，随每次刷新在
  父作用域求值并写入 props 容器（reactive 写入 → 模板绑定自动重求值）
- **slot**：模板内 `<slot/>` 标记；宿主标签的子节点（按父作用域求值）移入槽位；
  无子内容时移除槽位标记
- **子→父通信**：回调 props（`:on-tap="Handler"`，组件内 `props.onTap(...)`）——
  emits 机制的等价简化（同 React 约定），文档明示
- **watch deep**：`watch(fn, cb, { deep: true })` —— 内容快照比较（原对象可被原地修改，
  引用相等不代表内容相等）；变化时以 (新值, undefined) 回调

**测试**：runtests 扩至 **465 项全绿**（M7-3 新增 6 项）：组件实例化（静态 prop + 函数 prop）、
动态 prop 初始/随父更新、slot 内容与作用域、watch deep 基线/触发。

**已知边界（M7-4 候选）**：模板多根、具名 slot、props 类型校验、组件内 x-for 的键控作用域
与父级 keyed diff 的叠加语义。
（除"组件内 x-for 的键控作用域"作为验证项外，其余已于 M7-4 完成，见 §9。）

## 9. M7-4 实施记录（追加，2026-09-12）

**先修正两处既有缺陷（M7-2/M7-3 遗留）**

- **`ApplyForKeyed` 从未被调用**：M7-2 加入键控 diff 实现，但 `Flush` 对所有 `x-for` 一律走
  `ApplyFor`（长度重建），`x-key` 实际只是"不参与 diff 的普通属性"——既有用例断言的是可见结果，
  重建与复用结果相同，故一直被掩盖。现按 `KeyExpr <> ''` 分派：键控走 `ApplyForKeyed`
- **迭代作用域改用"复用环境 + 就地更新变量"**，不再给复用克隆逐条改写 `Scope`：
  每次复用只 `Define(itemName/index)`，组件实例等子作用域（父为迭代环境）自然看到新数据；
  顺带避免旧实现里 `Owner = 绑定` 的匹配条件漏掉组件实例绑定
- **`ApplyFor` 同长度元素替换就地更新**：原实现 `arr.Length = 容器子节点数` 即返回，
  `state.rows = [...]`（长度相同、元素换了对象）会一直显示旧数据；现比较迭代变量与数组元素
  （严格相等），不同则原地更新作用域，长度变化才重建
- **非键控克隆的作用域未登记为 GC 根**（`MarkScopes` 只看 `Items`，而 `Items` 原先只由键控路径写入）
  —— 现两条路径都登记条目簿记；`PropsObj` 也纳入根集
- **移除 `ApplyBinding` 中 `bkIf` 分支残留的调试 `WriteLn`**

**M7-4 功能**

- **组件模板多根**：`LoadDocumentFromXML('<xui-root>…</xui-root>')` 后按序摘出全部子节点，
  原位插入宿主位置；宿主 `id`/`class` 落到首个实例根；`ApplyNodeData`/`ScanNode` 逐根执行
- **具名 slot**：模板内 `<slot/>` = 默认槽、`<slot name="x"/>` = 具名槽；
  宿主直接子节点按 `slot="x"` 归属（移动时剥离该属性），未匹配槽位的内容连同其绑定丢弃
  （`PruneNodeBindings`：按子树 + Owner 链递归剪除，避免悬空绑定）
- **props 类型校验**：`props` 支持数组（仅声明）与对象形式（`a: 'number'` 或 `{type, required}`）；
  写入时校验，静态字符串属性先按声明强转（`"7"` → 7、`"true"` → true），不匹配则上报
  `ssRuntime` 并**保留旧值**；`required` 在实例化时一次性检查。类型名：
  `string/number/boolean/function/object/array/any`（`''`/`any` = 不校验）
- **组件替换宿主节点后的引用改写**：`ReplaceNodeRefs` 把条目簿记（`Items[].Node`）与
  `OwnerRoot` 上对宿主节点的引用改指实例首根——这是"模板根是组件"（keyed 列表项为组件）
  能正常重排/复用而不踩已释放节点的关键
- **slot 内容归属组件绑定**：宿主子节点以组件绑定为 `Owner` 登记（原为外层绑定），
  分发入槽后继续生效，被丢弃时随子树一并剪除
- **宿主上的 `x-if`**：原先绑定会指向被释放的宿主节点（悬空）；现单根实例把该绑定改指实例根
  （假值摘除、真值原位恢复照常作用于实例），多根实例无法整体摘除，明确上报不支持
- **`x-for` 容器缺少模板子节点**：上报 `ssCompile` 并不登记绑定（原来会克隆 nil 子树而崩溃）

**测试**：runtests 扩至 **491 项全绿**（M7-4 新增 26 项）：keyed 复用（节点对象保持/文本更新/
新 key 追加/无错误）、非键控同长度就地更新、多根模板与 id/class 归属、具名+默认 slot 与丢弃、
props 静态强转/动态类型不匹配上报且保留旧值/required、组件作为 keyed 列表项、组件内 x-for ×
父级 keyed 复用叠加、组件宿主 x-if（渲染/摘除/恢复）、多根组件 + x-if 上报、x-for 缺模板子节点上报。

**已知边界（M7-5 处理）**：多根组件作为 keyed 列表项只按首根重排、props `default` 未做
——均已在 §10 解决；attrs 透传与 keyed 的 LIS 最小移动仍为候选。

## 10. M7-5 实施记录（追加，2026-09-12）

- **props `default`**：声明对象支持 `default`；实例化时若宿主未提供该 prop 则套用。
  值可调用时视为**工厂函数**，每次实例化调用一次（对象/数组缺省因此不跨实例共享，同 Vue 约定）。
  缺省值同样走类型校验；`default` 指向的 JS 值（可为函数/数组）由绑定引擎的 GC 根回调保活
  （组件定义由注册表长期持有，故不能用会被 `ClearRoots` 清掉的宿主根）
- **多根实例作为 keyed 列表项的分组重排**：条目簿记重构为
  `TXuiForItem = 键 + 根集合（Nodes）+ 迭代作用域`（此前只有"首根"指针与平行的键列表），
  于是：`ReplaceNodeRefs` 把宿主节点整组改指实例根集合；重排按组搬移（组内保持连续，
  用游标前推，已就位则不动）；移除时按组内每个根剪除绑定（第二棵根下的绑定不再漏删）。
  原先"只按首根重排"的限制消除
- **簿记重排不再重建条目**：按 newKeys 顺序重排条目对象本身（`OwnsObjects` 暂关后重排），
  复用条目保留其作用域与根集合；求 key 共用一个临时作用域（解释器不回收环境对象，
  避免每次刷新新建 N 个环境）

**测试**：runtests 扩至 **497 项全绿**（M7-5 新增 6 项）：props default 原始值缺省/显式覆盖、
工厂函数缺省（数组 + 类型校验无错误）、多根组件作为 keyed 列表项的成组渲染与成组重排。

**已知边界（M7-6 候选）**：props 透传/attrs fallthrough 未做（lui 的 XML 属性还会绑定宿主行为，
透传语义需单独设计）；keyed 移动为逐条目搬移，未做 LIS 最小移动优化。

## 11. M7 演示页与随发现的修正（追加，2026-09-12）

**演示页**（`demo/m7.xml` + `demo/m7.ts` + `demo/m7-light.css` / `m7-dark.css`）

- 覆盖：插值 `{{state.n}}` 与 `computed` 取值、`x-model` 双向（输入框 ↔ 状态）、`:class` 对象语法、
  `x-if`、`x-show`、keyed `x-for`（添加 / 删首条 / 反转，x-key 复用）、`watch(deep)` 副作用、
  组件（props 类型与缺省、具名 slot + 默认 slot、函数 prop 在子模板内求值）
- 演示入口：`demo1 m7`（浅色）/ `demo1 m7 dark`（深色）/ `demo1 m7 demo shot`（模拟交互后截图）；
  `demo1.lpr` 的 `SimulateInteraction` 增加 m7 分支（+1 ×3 → 输入 → 添加 → 反转 → 切明细）
- 页内所有点击都走"脚本全局函数"回退路径；换肤复用宿主 published 方法 `ThemeClick`
- **应用内导航**：`demo/nav.xml` 以 `<include>` 进各页（登录/列表/待办/脚本/响应式），
  点按走宿主 published 方法 `PageClick`（按按钮 `to` 属性切页），宿主按当前页给按钮加 `active` 高亮；
  公共样式 `nav-light.css` / `nav-dark.css` 由 `ApplyTheme` 与页面主题一起加载
  （`demo1 login demo shot` 会在模拟交互末尾点一次导航，截图即为切换后的 m7 页——切页链路可自动核对）
- **关闭窗口后进程不退出的修复**：窗体原先手工 `TDemoForm.Create(Application)` 创建，
  LCL 的 `Application.MainForm` 恒为 nil → `TCustomForm.Close` 判定为非主窗体走 `caHide`（只隐藏），
  `Application.Terminate` 永不调用，消息循环继续跑（该问题自 M1 起就存在，只用手工窗体时不会退出）。
  现改用 `Application.CreateForm(TDemoForm, Form)`，窗体成为 MainForm → 关闭即终止应用
- **切页残留导致报错**：m7 页注册的 `watch(...)` 在切到脚本页后仍在跑，而 `state` 已被 script.ts
  重新定义成 `{n:0}` → 旧 watcher 求值 `nv.length` 抛"无法读取 undefined 的属性"，
  且该异常从 `RunWatchers` 一路逃到宿主顶层（LCL 弹异常框）。两处修正：
  1. 文档替换时清空页面级响应式登记（`TXuiJsInterp.ClearPageReactive` 清 watch/onMount）——
     上一页的监听器不再作用于新页面；
  2. `RunWatchers` / `RunMountHooks` 内未捕获异常只上报（`OnCallbackError`，与宏任务回调一致）
     不扩散——即便脚本写错也不会崩应用、不中断其余监听器。
  演示模拟里加了 m7 → 脚本页 → m7 的往返（换页后需先算一次布局，模拟里用 `engine.Draw(nil,...)`），
  并把"运行期无 `script-error.txt`"作为切页链路的核对手段

**随演示暴露并修正的引擎问题**（单测此前覆盖不到，因为测试总是"先跑脚本、再加载 XML"）

- **首轮绑定扫描早于脚本运行**：`RunDocumentScripts` 开头的安全点会先扫描文档，而 `component(...)`
  是在 `<script src>` 里注册的——于是真实应用（`demo1 m7`）里组件标签被当普通标签处理，
  组件永不实例化（页面上只看到写进去的 slot 内容）。现把"旧文档的最后排水"移到文档替换之前
  （`LoadFromFile`/`LoadFromString` 内），首轮扫描统一放在**脚本运行之后**的安全点
- **`reverse` / `splice` 未通知响应式写入**（push/pop/shift/unshift 都有）→ 反转/替换数组后
  UI 不刷新；两处补 `NotifyArrayWrite`
- **kebab-case 属性名未转 camelCase**：文档早先写的 `:on-tap="Handler"` → 组件内 `props.onTap(...)`
  实际不成立（prop 名保留连字符）；现按 Vue 约定转换（`:on-labels` → `onLabels`）
- 另新增 `x-for` 容器缺模板子节点时的错误上报（原来会克隆 nil 模板而崩溃）

**测试**：runtests 扩至 **512 项全绿**。导航轮新增 9 项：kebab→camel 函数 prop、数组
reverse/splice 刷新、`TestDemoPage` 整页加载演示页（无脚本错误 / 脚本注册的组件被实例化 /
插值 + computed 首渲染 / keyed x-for 初始 2 条 / 改状态后刷新 / 函数 prop 随 props 重新求值）；
第二轮新增 6 项：watch 求值异常上报且不执行回调/不阻断其它监听器（3 项）、演示页 m7 → 脚本页
切换无脚本错误/新页脚本生效/切页后脚本功能仍可用（3 项）。
