# lui M8 设计方案：组件库（对标 Element Plus）

> 状态：**设计待确认（2026-09-12）**。前置条件：M7 响应式绑定与组件系统已落地
> （`component()` props/slot/多根/x-for+x-key/x-if/x-show/x-text/`:class`/watch/computed，runtests 512 全绿）。
> 本文给出：现状盘点 → 关键决策（ADR 22–29）→ 组件分级清单 → 分期与验收 → 待你拍板的 4 个问题。

---

## 1. 目标与约束

**目标**：在 lui 之上做一套**纯库**组件库（XML 模板 + CSS 主题 + TS 逻辑），对标 Element Plus 的
*组件语义与写法*——`type`/`size`/`disabled`/`loading` 等 props、具名 slot、`on-*` 事件回调、
双向绑定、明暗主题；应用侧"引一次即用"，不要求改宿主 Pascal 代码。

**约束**（承袭项目既定约束）

- 零构建、零第三方依赖；组件库不引入新的构建步骤或外部资源
- 自研 TS 子集解释器：无 `Date`/`RegExp`/`Map`/`Set`，`Array` 缺 `sort/find/some/every`，`String` 缺 `padStart`
- CSS 子集（见 §2）：无变量、无伪元素、无阴影/变换、flex 子集
- 引擎只补**通用能力**（浮层、事件、测量、主题），不为单个组件开洞
- 非目标：Element Plus 全量 API 兼容；虚拟滚动/固定列；完整可访问性（受引擎键盘能力限制）

## 3. 关键决策（ADR 22–29）

### ADR 22 —— 组件事件：`x-onclick="expr"` 走绑定引擎（**M8-0 已实现**）

**问题**：G1。组件必须能把内部交互抛给父级。Vue 用 `emit`；lui 现有事件路径必须"名字可在宿主/全局查到"。

**实现（2026-09-12 落地）**：

- **写法**：`x-onclick="expr"`（等价别名 `x-on:click`）——事件触发时在**该绑定的作用域**（组件模板 /
  迭代克隆）求值；结果是函数则调用并传入事件对象，是别的值则视为语句表达式（如 `x-onclick="state.n = state.n + 1"`）。
  表达式形式还可读 **`event`** 变量（`x-oninput="state.t = event.text"`，对应 Vue 的 `$event`）。
  错误只上报 `ssRuntime`，不崩应用
- **输入事件载荷**：`xevInput` 此前用无载荷派发（`event.text` 恒空），现补上当前文本，
  组件内 `x-oninput="props.onModelValue"` 才能拿到值
- **不能用 `@click`**：laz2_dom 拒绝以 `@` 开头的属性名（`Name starts with invalid character 64`），
  XML 里根本无法表达 Vue 的 `@` 简写；原 M7 文档"`@click` 与 `onclick` 兼容"的说法从未成立
- **组件宿主上的语义**：`x-onclick="Expr"` 等价于回调 prop `:on-click="Expr"`（驼峰化为 `onClick`），
  即"父级监听子组件事件"的写法；组件模板内则写 `x-onclick="props.onClick"`
- **实现要点**：绑定引擎新增 `bkEvent` 绑定 + `TXuiBindEvent` 注册表（原生宿主函数 → 绑定），
  经新钩子 `OnNodeEvent` 让 DOM 桥注册/注销监听（复用 `node.on` 的监听表）；绑定删除统一走
  `DeleteBinding`（剪除克隆/改文档时自动注销监听）；处理器函数在 `MarkScopes` 中登记为 GC 根
- 顺带修复：`TXuiDomBridge.ResetBridges` 此前**无任何调用点**（桥缓存与监听表在换文档时从不作废，
  存在陈旧包装/陈旧监听按地址误命中的隐患）——现挂到 `OnResetBindings`，换文档时桥、监听、绑定登记一并清空

`onclick="Name"` 保持原语义（宿主 published 方法 → 脚本全局函数），两条路径并存、互不干扰。

### ADR 23 —— 组件双向绑定：`x-model` 扩展到组件（**M8-0 已实现**）

**问题**：G2。表单类组件没有 `v-model` 级别的写法会非常啰嗦。

**实现（2026-09-12 落地）**：`<ui-input x-model="state.name"/>` 在组件宿主上自动做两件事：

1. **读**：`props.modelValue` 绑定到宿主路径（走动态 prop 通路，含类型校验；路径变化即刷新）
2. **写**：注入函数 prop `props.onModelValue`，组件内部调用它即回写宿主状态

组件内部写法（例：包一层输入框）：

```xml
<panel class="ui-input"><input :text="props.modelValue" x-oninput="props.onModelValue"/></panel>
```

**取值约定**：`onModelValue(v)` 收到脚本值；若组件直接把**事件对象**传进来
（`x-oninput="props.onModelValue"`），引擎按 `value → text → 事件节点的 text` 顺序提取，
因此上面这行就是完整的双向绑定。显式的 `:model-value` / `:on-model-value` 优先（`x-model` 让位）。

实现要点：新增 `TXuiBindModel` 注册表（写回函数 → 路径）+ `WritePath`（与 `x-model` 输入框回写同规则，
`HandleModelInput` 也改为复用它）；绑定删除统一走 `DeleteBinding`（克隆剪除/换文档时释放）；
写回函数在 `MarkScopes` 中登记为 GC 根。

### ADR 24 —— 浮层：文档根挂载 + 定位（**M8-0 已实现**，方案 A）

**问题**：G3 + G4。Dialog/Dropdown/Tooltip/Select 面板必须能浮在内容之上且不被裁剪。

**实现（2026-09-12 落地）**：

- **挂载**：`engine.AttachToOverlay(node)` —— 把节点移到**文档根**下：不再受祖先 `overflow:hidden`
  裁剪；定位元素按 z-index 排序在文档序之后绘制，因此天然浮在普通内容之上（同窗口仍是单棵树）
- **定位**：`engine.PlacePopup(popup, anchor, placement, offsetX, offsetY)`
  - placement：`bottom-start`（默认）/ `bottom` / `bottom-end` / `top-start` / `top` / `top-end` /
    `left` / `right` / `center`
  - 位置由当前布局的 `BoxRect` 计算；超出文档根内容区时**夹取**、下方放不下则**翻到锚点上方**
  - 结果写进**内联 style**（`position:absolute; left/top`）——随样式重算保留；
    与既有内联声明**合并**（作者写的 width/height 不会被覆盖）
  - `anchor = nil` 时按文档根内容区定位（`center` 可用于对话框居中）
  - 浮层内容尺寸变化后再次调用即可重新对齐（v1 不做自动观察）
- **脚本接口**：`ui.popup(node, { anchor: <节点|id 字符串>, placement, offsetX, offsetY })`；
  新增 `node.rect`（`{left, top, width, height}`，来自最近一次布局）供脚本测量
- **库侧用法（M8-3 起）**：组件显示浮层时调用 `ui.popup(...)`；若后续觉得要写脚本不便，
  可再补声明式 `x-popup="<anchorExpr>"`（绑定引擎每轮刷新托管挂载+定位），列为 M8-3 可选项

**仍未做（记为后续候选）**：`position: fixed` 与真正的 portal/层叠上下文（当前 z-index 只在同级
兄弟间排序）；浮层随锚点滚动/尺寸变化的自动跟随；遮罩层与焦点锁（M8-3 在库层实现）。

### ADR 25 —— 主题：CSS 变量（**M8-0 已实现**，方案 B）

**问题**：G6。Element Plus 靠 `--el-color-primary` 等变量做主题与尺寸阶梯；lui 原先无变量。

**实现（2026-09-12 落地）**：

- **声明**：规则里写 `--ui-brand: #1677ff;`（自定义属性不分标签，`window { --ui-*: … }` 即全局 token）
- **取值**：任意声明值里写 `var(--ui-brand)` / `var(--missing, #ff0000)`（带回退）；
  简写值内可混用（`border: 1px solid var(--ui-brand)`）
- **继承**：变量表存在计算样式上并随继承向下传递（子孙规则可见祖先定义的 token，
  同 CSS 语义）；**层叠优先级**：普通规则 → 内联 `style` → `!important`，同名后者胜，
  因此"后加载的主题覆盖表"能整体换肤
- 实现要点：`TXuiStyle.Vars`（随 `InheritFrom`/`Assign` 传递）；`ComputeNodeStyles` 内联
  style 只解析一次，先按优先级**收集变量**再做**值替换**（`var()` 可嵌套解析，最多 4 层，
  未定义且无回退则替换为空串使该声明失效）
- **踩坑记录**：CSS 解析器把值按 token 重新拼接，`var(--x)` 会变成 `var ( --x )`；
  替换前需规整括号相邻空格（`FindVarStart`/`NormalizeParenSpacing`）。
  注：颜色解析本身会去掉所有空格，所以此前 `rgba(...)` 一直正常，掩盖了这个特性

**验证**：runtests 新增 5 项（祖先定义可见 / 简写值内替换 / 未定义用回退 / 长度值替换 /
后加载样式表重定义变量后生效）。

### ADR 26 —— 命名与打包（**零构建的落地形态**）

- **标签前缀**：`ui-`（`<ui-button>`、`<ui-input>`、`<ui-dialog>`）；短名可选（`<ui-btn>` 记为别名，不做）
- **类名前缀**：`ui-`，状态类 `is-*`（`is-disabled`/`is-active`/`is-loading`），尺寸/类型修饰
  `ui-btn--primary`/`ui-btn--small`——与 Element Plus 的 `el-btn`/`el-button--primary` 心智一致
- **目录**：
  ```
  ui/
    index.ts              # 入口：注册全部组件（component(...) 调用）+ 导出工具（如 FormRegistry）
    theme/lui-light.css   # token + 基础样式（浅色）
    theme/lui-dark.css    # token + 基础样式（深色）
    components/button.ts  # 一个组件一个 .ts（props 声明 + 模板字符串 + 内部状态）
    components/input.ts
    components/dialog.ts
    templates/button.xml  # 可选：模板外置（需引擎支持 templateFile，见 ADR 27）
    README.md             # 用法、组件清单、与 Element Plus 的差异表
  ```
- **应用接入**（3 步）：
  ```xml
  <script src="../ui/index.ts"/>
  ```
  ```
  engine.LoadStyleSheetFromFile('ui/theme/lui-light.css');   // 宿主侧；或由 demo/应用自行加载
  ```
  demo 增加一页 `demo1 ui`（组件库总览页）+ `ui-form`/`ui-dialog` 等专页。

### ADR 27 —— 模板外置（**M8-0 已实现**）

**实现**：`component('ui-button', { props: {...}, templateFile: 'templates/button.xml' })`
——引擎在**注册时**读取该文件作为模板；相对路径按**当前正在求值的脚本文件所在目录**解析
（`TXuiScript.CurrentFile`，无脚本上下文时退回进程工作目录），绝对路径原样使用；
文件缺失/读取失败上报 `ssCompile`。`template` 与 `templateFile` 同时存在时 `templateFile` 优先；
脚本重新求值（换页/热重载 XML）时会重新读取文件，因此改模板后重载页面即可生效。

收益：组件模板是真正的 XML（可高亮、可 include 片段、可热重载），库作者不必把模板塞进 `.ts` 字符串。

### ADR 28 —— 图标：先字形层，后 image

G7/G8：无伪元素、无背景图、`image.src` 未实现。首版用 **Unicode 字形 + 固定字形表**
（`ui/icon.ts`：`{ close:'✕', check:'✓', arrow:'▾', loading:'◌', … }`，组件通过 `icon` prop 使用），
CSS 里用等宽/居中规则保证对齐；后续若你要求"真图标"，再补 ①`image` 渲染（PNG，无矢量）
或 ②CSS 画简单形状（无 transform 时能力有限）。

### ADR 29 —— 表单与校验：库内注册表 + 受控 props（不改引擎）

组件拿不到"父组件实例"（没有 provide/inject），因此表单协议走**显式约定**：

- `<ui-form id="f1" :model="state.form">`：把 model 对象（reactive）传给表单
- `<ui-form-item form="f1" prop="name" :rules="…">`：`form` 用 **id 字符串**关联（库内
  `FormRegistry` 是一个 `reactive` 全局表，key = form id）
- 校验时机：`blur`/`change`/`submit`（`@blur` 依赖 ADR 22）
- 应用提交：`<ui-button :on-click="OnSubmit">` → `OnSubmit` 调 `uiForm.validate('f1')`（库导出的全局函数）
- 状态类：`is-error` + 错误文案节点（slot `error`）

键盘可访问性（G5）本阶段仅"Tab 可达 + Enter 激活"；方向键/Esc/Home/End 记为引擎后续补口，
届时 Select/Menu/Tabs 升级为完整键盘操作（组件库预留 `keyboard` 分支，先按鼠标路径实现）。

### ADR 30 —— 基础控件的实现位置

| 方案 | 说明 | 代价/收益 |
| --- | --- | --- |
| **A 纯库自绘（推荐）** | checkbox/radio/switch/slider 用 `panel`+`label` + `:class` 状态 + 字形符号画（`✓`/实心圆/滑块），逻辑在 TS | 与"组件库"定位一致；鼠标可用，键盘需引擎补 tabindex/keydown（后续） |
| B 引擎加行为类 | 每个控件写 Pascal `TXuiBehavior`（可聚焦 + 键盘 + 原生观感） | 引擎膨胀、跨平台绘制成本高；与组件库"零构建纯数据"路线分叉 |

**推荐 A**，只在**通用能力**上动引擎（ADR 22–24、27）。

## 4. 组件清单与分级（对标 Element Plus）

分级依据：**L0 布局基础 → L1 表单基础 → L2 数据展示 → L3 反馈浮层 → L4 导航 → L5 高级（依赖 G9 或暂缓）**

| 级别 | Element Plus | lui 计划 | 依赖补口 | 说明/降级 |
| --- | --- | --- | --- | --- |
| L0 | Row/Col/Container/Header/Aside/Main/Footer/Space/Divider/Card/Link/Text/Icon | `ui-row/ui-col/ui-space/ui-divider/ui-card/ui-link/ui-text/ui-icon` | — | Col 只支持 24 栅格 + gutter（无响应式断点，@media 不支持） |
| L1 | Button/ButtonGroup/Input/InputNumber/Checkbox/Radio/Switch/Slider/Rate/Form/FormItem | 同名 `ui-*` | ADR 22/23/29 | Input 用现有 input 行为；InputNumber=Input+脚本；无 textarea（引擎缺），改用 Input+多行绘制（**延后**） |
| L2 | Tag/Badge/Progress/Avatar/Table/Pagination/Collapse/Tooltip/Popover | `ui-tag/ui-badge/ui-progress/ui-avatar/ui-table/ui-pagination/ui-collapse/ui-tooltip/ui-popover` | ADR 24（Tooltip/Popover） | Table：无固定列/虚拟滚动/横向滚动；排序需补 `Array.sort` 或库内实现排序 |
| L3 | Dialog/Drawer/Message/MessageBox/Notification/Alert/Loading | `ui-dialog/ui-drawer/ui-message/ui-message-box/ui-notification/ui-alert/ui-loading` | ADR 24 | Dialog 走 overlay+遮罩；Message/Notification 为命令式（`uiMessage.info('…')`，库内建 overlay 容器） |
| L4 | Tabs/Menu/Breadcrumb/Dropdown/Steps/PageHeader/Backtop | `ui-tabs/ui-menu/ui-breadcrumb/ui-dropdown/ui-steps/ui-backtop` | ADR 24 + G5 | 方向键导航缺，先按点击/悬停 + Tab 可达；Backtop 依赖滚动监听（`onwheel`+`node.scrollTop` 可得） |
| L5 | DatePicker/TimePicker/Upload/Tree/Transfer/Cascader/ColorPicker/Carousel/Affix/Table 高级 | 部分 | G9 + G3/G5 | **本期不做**，先补 `ui.now` 墙钟与 TS 日期工具，其余按需评估 |

**明确不做（并写入 README 差异表）**：虚拟滚动、固定列、图片/图标字体、原生 `select` 下拉、

## 6. 与 Element Plus 的写法对照（示例）

```xml
<!-- 应用侧（lui） -->
<ui-button type="primary" size="small" :disabled="state.busy" :on-click="OnSave">保存</ui-button>

<ui-input x-model="state.name" placeholder="请输入用户名" clearable/>

<ui-form id="f1" :model="state.form">
  <ui-form-item form="f1" prop="email" label="邮箱" :rules="[Rules.required, Rules.email]">
    <ui-input x-model="state.form.email"/>
  </ui-form-item>
</ui-form>

<ui-dialog :visible="state.showDlg" title="确认" :on-close="OnCloseDialog">
  <label class="ui-text" text="内容来自默认 slot"/>
</ui-dialog>

<ui-table :data="state.rows" :columns="state.cols"/>   <!-- columns: [{prop,label,width,sortable}] -->
```

> 与 Vue/Element Plus 的差异（README 中明示）：事件用 `:on-xxx` 函数 prop 而非 `@xxx`（父级侧）；
> 组件内部用 `@click="props.onXxx"`（引擎补口后）；`v-model` → `x-model`；无 `v-slot` 简写，
> 具名槽用子节点 `slot="name"`。

## 7. 风险与取舍

1. **G3/G5 是天花板**：没有 fixed/portal/层叠上下文与键盘事件，Dialog/Dropdown/Select 的观感与
   可访问性只能做到"够用"。M8-0 的 overlay 方案能覆盖 Dialog/Tooltip/Select 面板，但**跨窗口/多浮层嵌套**
   与**滚动边界夹取**要靠宿主 `PlacePopup` 兜住，脚本侧定位不灵活。
2. **无阴影/变换**：浮层与卡片的"层次感"只能靠 1px 边框 + 背景色差；Element Plus 的观感会明显降级。
3. **双主题表维护**：token 表两份，新增组件要在两处保持一致（可在 `.ts` 里只写类名、样式集中在两张表，
   降低漂移概率；若采纳 ADR 25-B 则合并为一份 + 覆盖表）。
4. **文档-代码一致性**：本项目已经出现过多处"文档声称、代码未实现"（`@click`、`:on-tap` 驼峰、
   fs 用例）。M8 起约定：**每个 ADR 落地时同步补 runtests 用例**，文档只写"已验证"的事实。
5. **TS 子集能力**：无 `Date`、`sort`、`find` 会让 DatePicker/Table 排序写得更笨；库内先自带小工具
   （`sortBy`/`findIndex` 手写循环），必要时再补运行时。

## 8. 决策结论（2026-09-12 已拍板）

| # | 问题 | **决定** | 影响 |
| --- | --- | --- | --- |
| D1 | 主题方案 | **B：引擎实现 CSS 变量**（`--x` 声明 + `var(--x, fallback)` 取值） | 落地提前到 M8-0（组件库地基），M8-1 起只写一份 token 表 + 主题覆盖表 |
| D2 | 基础控件实现位置 | **A：纯库自绘**（XML/CSS/TS，引擎不加控件行为类） | 引擎只补通用能力；键盘交互随 G5 补口再升级 |
| D3 | M8-0 补口范围 | **②：事件表达式 + 组件双向绑定 + 模板外置 + 浮层 overlay 与定位** | Dialog/Dropdown/Tooltip/Select 面板在 M8-3/M8-4 可落地 |
| D4 | 起步批次 | **①：L0+L1 一批交付** | M8-1 同时出布局基础与表单基础，先跑通"按钮 + 输入 + 表单"闭环 |

> 后续实现按 §5 分期执行：M8-0 逐项落地并各自补 runtests 用例（文档只写"已验证"的事实），
> 每项独立提交；M8-0 完成后再进 M8-1 的组件批次。
