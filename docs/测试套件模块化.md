# 测试套件模块化

`tests/runtests.lpr` 仍是唯一的 Pascal 回归入口，但测试实现按能力域拆分为
独立的 `.inc` 文件。这样可以保持 Free Pascal 的单程序执行模型，同时避免在
一个文件中维护所有里程碑测试。

## 当前分组

| 分组 | include |
| --- | --- |
| XML/CSS 基础、块布局 | `core_css.inc`、`core_layout.inc` |
| M3 布局 | `layout_*.inc` |
| M4 事件与命中测试 | `event_*.inc` |
| M5 输入、过渡、include | `input_*.inc`、`include_templates.inc` |
| M6 脚本、Promise、定时器、I/O | `script_*.inc` |
| M7 响应式与演示页 | `script_reactive.inc`、`script_demo_page.inc` |
| M8 CSS 变量与组件库 | `css_variables.inc`、`ui_library.inc` |
| M10 Agent 演示页 | `agent_page.inc` |
| M11 宿主、脚手架和小型回归 | `host_regressions.inc`、`scaffold_regression.inc`、`remaining_regressions.inc` |

入口按依赖顺序统一引入这些文件；共享的 fake renderer、脚本 sink 和测试辅助
仍保留在 `runtests.lpr` 的公共区域，避免 include 之间形成循环依赖。

## 迁移约定

当前迁移采用“活动 include + 旧实现保留”的阶段性策略：

1. 新 include 提供正式测试过程；
2. 旧实现改名为 `*Inline` 或置于未定义的 `LUI_*_INLINE` 条件块中；
3. 每次迁移都必须通过完整 `npm test`，并保持机器可读基线不变；
4. 后续清理阶段可删除旧实现，不应改变测试注册顺序或断言数量。

当前回归基线为 **722 项通过、0 项失败**。验证入口是：

```bash
npm test
```
