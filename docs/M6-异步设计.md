## 0.1 P0 实施记录（已完成）

**交付单元**：`xui_script`（门面）、`xui_script_dom`（DOM 桥）新建；
`xui_engine` / `xui_host` / `xui_dom` / `xui_xml` / `xui_js_runtime` 扩展。

**能力**
- **脚本加载**：XML `<script src="app.ts"/>`（解析期收集，不产生节点；相对路径按 XML 目录解析），
  文档加载完成后按出现顺序求值；缺文件只上报不中断
- **门面**（`xui_script`）：编译缓存（按文件名）、求值、**执行切片 InvokeSlice**（重置预算 + 错误路由）、
  原生注册（`RegisterNative('ui.xxx')`，后续功能的统一挂点）、GC 根管理、错误阶段分类
  （`ssCompile/ssRuntime/ssUnhandledRejection/ssIO/ssBudget`）
- **DOM 桥**（`xui_script_dom`）：`document.find/add/body`；
  `node.id/tag/text/class/disabled/scrollTop/count/parent`（写入一律经引擎 API，样式与布局正确失效）、
  `node.find/hasClass/at/on/off/add/remove/clear/eachChild`；
  事件对象 `{type,node,x,y,delta,key,text,shift}`；桥对象对节点弱引用，DOM 变更前 `ResetBridges` 作废缓存
- **事件解析顺序**（`DispatchEvent`）：① 宿主 published 方法（RTTI，兼容既有页面）→
  ② **脚本全局同名函数**（惰性查询，脚本热重载后立即生效）→ ③ 脚本事件钩子（`node.on` 动态绑定）→
  ④ 节点行为 → ⑤ `OnEvent` 兜底
- **安全点** `SafePoint`：已在鼠标移动/抬起、键盘、文本输入、文档加载、Tick 处就位（P1 起用于排水）
- **错误路由**：宿主写入 `script-error.txt` 并在存在 `#msg` 节点时页面内提示
- **缺陷修复**：指令预算改为**按切片重置**（原实现跨调用累积，长跑应用会误报死循环）；
  预算超限改抛**脚本异常**（可被脚本 `try/catch` 捕获，未捕获才上报）

**过程中修复的关键 bug**（均为既有实现的缺陷，由 P0 集成测试暴露）
1. **派生类实例化丢 `this`**：无显式构造函数的派生类走 `new` 时，父类构造函数被放在新环境执行，
   导致 `this` 为 undefined（`new B("x")` 报"无法给 undefined 赋值"）→ 新增 `RunImplicitCtor`，
   沿继承链**共享同一个 this** 执行函数体，随后自基类向派生类依次做字段初始化
2. **字段初始化只生效一次**：`RunFieldInits` 结束会清空 `FieldInits` 表，同类第二次实例化字段不初始化
   → 移除清空（初始化表是类定义的一部分）
3. **预算超限不可捕获**：原抛 `EXuiJsRuntime`（Pascal 异常），脚本 `try/catch` 接不住 → 改抛 `EXuiJsThrow`

**测试**：runtests 扩至 **302 项全绿**（新增 25 项：内核 8 + 集成 17）；
既有 277 项无回归（未加载脚本的应用零额外开销）。

**验收**：新增 `demo/script.xml` + `demo/script.ts` + 双主题 CSS，
逻辑全部在脚本侧（XML 的 `onclick="OnAdd"` 回退到脚本全局函数）；
`demo1 script demo shot` / `demo1 script dark demo shot` 截图核对通过；
`todo`/`login`（仍在用宿主 RTTI 绑定）截图与之前完全一致。

## 0.2 P1 实施记录（已完成）

**交付单元**：`xui_js_runtime` 扩展（Promise / 微任务队列 / 预算切片化 / GC 根扩展）；
`xui_script`（排水接入切片与求值、未处理拒绝路由）；`xui_engine`（SafePoint 排水）。

**能力**
- **Promise 完整可用**：`new Promise(executor)`（同步执行；executor 抛错即拒绝；
  resolve/reject 控制函数经函数 Tag 携带目标 promise）；原型 `then/catch/finally`
  （返回下游 promise；非函数参数透传）；静态 `resolve/reject/all/allSettled/race`
  （`resolve` 对原生 promise 原样返回；`all`/`allSettled` 参数 v1 简化为数组、结果按输入下标写回；
  `race` 先到先得，非 promise 值按 FIFO 入队参与竞争）
- **thenable 采纳**：resolve 的值或回调返回值是 promise → 下游跟随其 settle（透传反应）；自引用拒绝
- **微任务队列**：settle 时把反应项拷贝为**自持作业**（冻结状态与值，不再引用上游 promise），
  FIFO 排空；排水重入防护（排水期间新增任务由同一轮继续排空）；
  作业内的脚本异常按 Promise 语义 reject 下游，不被吞掉
- **预算切片化（修缺陷）**：每个微任务进入时 `FSteps := 0`（不继承触发切片的已耗步数，
  挂起等待不累计）；`RunUnit` 亦重置（多文件顺序求值不互相累计）；
  预算超限以脚本异常冒泡 → reject 下游 → 未处理上报仍按消息文本归类为 `budget`
- **GC 根扫描扩展**：微任务队列（回调/参数/下游）、未处理拒绝表、聚合收集状态、
  resolve/reject 控制函数经 Tag 保活其 promise
- **未处理拒绝**：rejected 且无人挂接处理 → 进入表；任何 then/catch/finally 挂接即移除；
  排水结束统一上报**一次**（`OnScriptError`，stage=`unhandledRejection`；预算超限归类 `budget`）
- **安全点排水落地**：引擎 `SafePoint`（鼠标/键盘/文本输入事件结束、文档加载、脚本求值后、Tick 内）
  调用 `Script.DrainMicrotasks`；门面 `InvokeSlice` / `RunUnit` 退出时排水；
  事件切片结束时回调改 DOM 立即生效（样式与布局正确失效），无需等待 Tick

**实现取舍（与 §4 的差异）**
- `Handled: Boolean` 位以"未处理表 + 挂接即移除"实现（等价语义）
- `all`/`allSettled` 的共享收集状态由解释器持有的 `TXuiJsAggregate` 承载，任务跑完即回收（避免长链泄漏）
- `finally` 回调返回值忽略（v1 简化）；回调抛错则下游拒绝
- 微任务出队用 `Extract` 而非 `Delete`（自有列表 `Delete` 会立即释放任务对象，
  自测暴露的 use-after-free，已修复）

**测试**：runtests 扩至 **352 项全绿**（新增 50 项：Promise 语义 21 / 微任务时序与错误路由 9 /
预算切片化 5 / GC 与保活 11 / 引擎集成 4）；既有 302 项无回归。
覆盖：回调异步性与经典顺序断言、FIFO、链式传值、透传、错误传播与恢复、状态不可逆、
executor 同步与抛错、采纳、`all`/`allSettled`/`race`（含普通值混入与空数组）、`finally` 三路径、
未处理拒绝上报一次/挂接免报/不重复上报、微任务死循环超预算、
跨任务预算不累计（含 1.5× 预算正负对照）、挂起对象存活与排水后收敛、
GC 后控制函数仍可用、事件切片排水改 DOM、`unhandledRejection`/`budget` 错误分类。

**验证**：`lazbuild tests\runtests.lpi` → `tests\runtests.exe` → 352 通过 0 失败；
`demo1` 编译通过（当时有运行中的实例占用 exe，链接以 runtests 验证）。

## 0.3 P2 实施记录（已完成）

**交付单元**：`xui_js_runtime` 扩展（定时器表 / 宏任务泵 / `ui.*` 定时器 API）；
`xui_script`（时钟注入 / 泵与错误路由宿主接口）；`xui_engine`（Tick 泵 + `NeedsTick` 计入）。

**能力**
- **`ui` 定时器 API**（运行时注册，bridge 等后续 `ui.*` 注册并入同一对象）：
  `ui.setTimeout(fn, ms, ...args)` / `ui.setInterval(fn, ms, ...args)`（返回 Id，额外参数作回调实参）、
  `ui.clearTimeout(id)` / `ui.clearInterval(id)`（同一 ClearTimer：置 Cancelled，泵内回收）、
  `ui.delay(ms): Promise`（基于定时器，到点 resolve(undefined)）、`ui.now()`（返回注入时钟）
- **表项** `{Id, Callback, Args, DueMs, Interval, Cancelled}`；`Tick` 内取 `DueMs <= FClock` 执行；
  到期顺序按 DueMs 排序，同期按注册序（FIFO）；一次性执行后出表，`setInterval` 固定间隔重排
  （不做漂移补偿）；间隔下限 1ms（`setInterval(fn,0)` 钳制，泵可在有限时钟内终止）
- **宏任务切片**：每个回调前重置预算；回调结束后排水微任务（**微任务优先于下一宏任务**）；
  回调内未捕获异常经 `OnCallbackError` 上报（stage=`runtime`；预算超限文本归类 `budget`），
  **不中断后续定时器与应用**；泵重入防护
- **时钟注入**：`Script.SetClockMs(ANowMs - FScriptClockBase)`（相对应用零点），
  测试可直接人造推进断言顺序；GC 根扩展：定时器表（回调与参数）
- **`NeedsTick` 计入"定时器表非空"**：宿主 Timer 按需启停，无需改宿主

**测试**：runtests 扩至 **385 项全绿**（新增 33 项：内核 13 / 引擎集成 5 …）。
覆盖：`setTimeout(0)`、到期顺序（延迟排序 + FIFO）、`clearTimeout`、`setInterval` 重复与停止、
零间隔钳制、微任务优先于下一宏任务、额外参数、`ui.delay` 到点 resolve、`ui.now` 相对时钟、
回调异常上报不中断、宏任务死循环超预算、定时器回调 GC 保活、
引擎 `NeedsTick` 开/关、Tick 泵改 DOM、宏任务异常/预算错误分类。

**验证**：`lazbuild tests\runtests.lpi` → `tests\runtests.exe` → 385 通过 0 失败。

## 0.4 P3 实施记录（已完成）

**交付单元**：`xui_js_parser`（nfAsync / nkAwait / nfHasAwait 传播 / await 位置校验）；
`xui_js_runtime`（显式控制栈可挂起求值器、帧栈异常展开、GC 根扩展）。

**解析器**
- `async function` 声明/表达式、`async` 箭头（单参与参数表）、类方法与对象字面量 async 方法
  （统一置 `nfAsync`；`async()`/`async:` 等仍解析为名为 async 的成员）
- `await` 作为一元前缀（`nkAwait`），解析期位置校验：仅 async 函数体内合法
  （非 async 函数/顶层 → 「await 只能用于 async 函数内」带行列；`for await..of` → 明确报错）
- `nfHasAwait` 后处理自底向上传播（XuiJsParse 末尾一次全树遍历）：nkFunc 子树**内部照常标记、
  节点自身不被污染**（求值闭包不执行函数体）；注意不能用 or 短路表达式（右子树会漏标记，
  自测暴露的缺陷）
- await 上下文栈（FAsyncCtx）：进入函数体压入 isAsync、退出弹出

**运行时（ADR 16 方案 B：显式控制栈可挂起求值器）**
- 快慢双路径：子操作数无 `nfHasAwait` → 委托既有递归求值器同步算完（零改动零回归）；
  含 await → 压入子帧，完成时交付回父帧槽位
- 帧栈按「节点种类 × 相位」推进，每相一停；已覆盖全部可含 await 的节点：
  表达式（await/二元/逻辑/条件/赋值/一元/模板/数组/对象/Seq/成员链调用/`new`），
  语句（块/表达式语句/声明/if/while/do-while/for/for..of/return/throw/break/continue/try）
- `nkAwait`：被等待值是 promise → 挂 rkResume 反应（settle 时拷贝为恢复任务）；
  非 promise → 直接排微任务（等价 `await Promise.resolve(v)` 的延迟语义）→ 机器挂起、切片退出
- async 函数调用（`CallAsyncFunction`）：建机器同步跑到首个 await 即返回 promise；
  内部未捕获异常 → reject promise（async 函数永不同步抛出）
- 异常展开：自栈顶找**仍在本保护范围内**的 try 帧（catch → finally → 重抛；
  finally 自身抛出则覆盖原异常向外传播）；finally 的控制流覆盖原结果
- 赋值目标读写（WriteRefTo/ReadRefTo）与 EvalExpr 内嵌逻辑保持一致；
  复合赋值目标含 await、`delete`/自增目标含 await → 明确报"暂不支持"
- GC 根扩展：活跃机器（FAsyncCalls）的帧栈（环境/操作数/结果/被采纳迭代数组）、
  rkResume 反应与恢复任务中的机器引用

**过程中修复的缺陷（由矩阵测试暴露）**
1. nfHasAwait 传播用 or 短路 → 双 await 表达式的右子树漏标记（同步求值器兜底报错）
2. 实参交付复用槽 0，覆盖成员链的被调者（finally-await 用例 AV）
3. PromiseSettle 在清空 Reactions **之后**判断 Count=0 → 所有经透传链的拒绝被误报未处理

**测试**：runtests 扩至 **409 项全绿**（新增 24 项：await 矩阵 14 / 位置校验 3 / 错误与预算 3 /
GC 1 / 引擎集成 3）。覆盖：同步执行到首个 await 的经典顺序、表达式内 await、可选链+`??`、
while 条件 / for..of 源 / for 步进、含 await 的 try/catch/finally（finally 内 await 后仍透传）、
`return await`、嵌套 async、异步递归（同表达式双 await）、async 方法/箭头/字面量、
async 抛错拒绝传播与未处理上报、位置校验三类报错、async 死循环超预算可捕获、
挂起帧栈 GC 后可恢复、引擎级 `await ui.delay` 序列改 DOM。

**验证**：`lazbuild tests
untests.lpi` → `tests
untests.exe` → 409 通过 0 失败。

## 0.5 P4 实施记录（已完成）

**交付单元**：`xui_script_io`（新建：I/O 工作线程、完成队列、WinHTTP 直声明、文件读写、
`ui.http`/`ui.fs`/`ui.storage` 注册与 Promise 桥接）；`xui_js_runtime`（公开 IO 桥 API、
`OnCollectRoots` GC 根回调、JSON.parse）；`xui_script`（懒创建 IO、`PumpIO`、`IoInFlight`、
stage=io 错误路由）；`xui_engine`（Tick 完成泵 + `NeedsTick` 计入在途请求）。

**能力**
- **`ui.http.get(url, opts?)` / `ui.http.post(url, body, opts?)`**：Promise<Response>；
  opts 支持 `timeout`（毫秒，默认 30s）与 `headers`（对象）；`opts.signal` 传入即报"暂不支持"
- **Response 对象**：`{status, headers, text(), json()}`；`json()` 依赖新增的 **JSON.parse**
  （递归下降方法组实现：对象/数组/字符串（含 \u 转义）/数字/true/false/null，错误带中文与位置）
- **`ui.fs.readText(path)` / `ui.fs.writeText(path, text)`**：Promise<string/void>，UTF-8 原始字节
- **`ui.storage.get(key)` / `ui.storage.set(key, value)`**：同步内存字典（缺失键返回 null）；
  `StorageFile` 非空时按 name=value 行持久化
- **线程铁律（ADR 18）落实**：工作线程只做系统调用（WinHTTP/TFileStream），跨线程只传
  "原始数据 + 状态码 + 请求 Id"；Promise settle 与 JS 值转换全部在主线程 `PumpCompletions`
- **完成回传**：工作线程写完成队列（临界区保护），引擎 Tick 泵排空 → settle → SafePoint 排水；
  完成延迟 ≤ 一个 Tick（宿主 Timer 16ms），与文档一致
- **NeedsTick 计入在途请求数 > 0**；I/O 失败 reject `Error` 并经 `OnScriptError(stage=io)` 记录，
  不中断应用
- **GC**：挂起请求的 resolve/reject 控制函数（连同 Tag 的 promise）经 `OnCollectRoots` 保活，
  完成后随挂起表释放
- **可注入 fake**：`SyncMode = True` 不开工作线程，`Executor` 可注入确定性 fake 执行器
  （测试不依赖真实网络）；文件往返测试走真实 TFileStream 路径

**实现注记**
- 控制函数经既有 `NativePromiseCtl`（Tag 携带目标 promise）复用 P1 的 settle 管线
- 方法自递归必须带括号：无括号函数名在本 FPC 语义下是 Result 变量引用而非调用
  （矩阵测试暴露，见 JsonParseValue）

**测试**：runtests 扩至 **428 项全绿**（新增 19 项：JSON.parse / fs 往返 / http 响应对象 /
json() / 完成顺序 FIFO / 超时 reject / 缺文件 reject / storage 读写 / signal 拒绝 /
在途计数 / 引擎 Tick 泵改 DOM / NeedsTick 开关）。

**验证**：`lazbuild tests\runtests.lpi` → `tests\runtests.exe` → 428 通过 0 失败。

## 1. 背景与现状（已核实）

**已确认的三个决策**

| 决策 | 结论 |
| --- | --- |
| await 范围 | **完整 await**：任意表达式位置、`try/catch/finally`、循环条件、可选链内 |
| 异步事件源 | **一并做真实 I/O**：`ui.http` / `ui.fs` / `ui.storage`（定时器之外） |
| 排序 | **先补完 M6-3 引擎集成，再做 async/await**（M6-3 是 async 的运行基质） |

**现状事实**

| 事实 | 位置 |
| --- | --- |
| `async`/`await` 三处被显式拦截 | `xui_js_parser.pas:1178`（语句）、`:1563`（表达式）、关键字表 `xui_js_token.pas:102` |

## 2. 目标与非目标

**目标**
- `Promise` 完整可用：`then/catch/finally`、`Promise.resolve/reject/all/allSettled/race`
- **完整 await**：表达式内（`1 + await f()`）、可选链（`(await g())?.v`）、`try/catch/finally`、
  循环条件（`while (await more())`）、迭代源（`for (const x of await list())`）、异步递归
- 定时器：`ui.setTimeout/clearTimeout/setInterval/clearInterval/ui.delay/ui.now`
- 真实 I/O：`ui.http.get/post`、`ui.fs.readText/writeText`、`ui.storage.get/set`
- 语义可测：人造时间推进即可断言微任务/宏任务顺序

**非目标**
- 顶层 await、`for await..of`、生成器语法（`function*`/`yield`）——挂起机器届时已具备，语法后置
- `AbortSignal` 取消（v1 不做；接口预留 `opts.signal` 位）
- 脚本级并行/多隔离区、在 worker 线程里跑脚本
- `queueMicrotask` 与 HTML 事件循环规范的完整细节（v1 为"微任务优先于下一宏任务"的简化模型）

## 3. 事件循环与安全点（架构主干）

```
主线程（唯一执行脚本的地方）
  ┌─ 微任务队列（Promise reactions / async 恢复）
  └─ 宏任务队列（到期定时器 / I/O 完成回调）
        ▲                        ▲
        │                        │ 完成回传（仅原始数据 + 状态码）
   SafePoint 排水          I/O 工作线程（只做系统调用，不接触 JS 值）
```

**执行切片（Slice）**：一次不可中断的脚本执行单元。四类入口：
① 加载后初始化求值 ② 事件分发中的脚本调用 ③ 单个微任务 ④ 单个宏任务回调。
每次进入切片：重置预算（§8）、捕获异常、退出时排水一次。

**安全点（SafePoint）**——只有"动 DOM 安全"的时刻才允许排水：
- 事件分发结束（`HandleMouseDown/Up/Move/Wheel/KeyDown/TextInput` 返回后）
- `Tick` 中：处理完到期定时器与 I/O 完成回传之后
- 文档加载完成、脚本求值结束后
- **明确禁止**：布局/绘制/命中测试中途、过渡插值中途（会破坏迭代中的 DOM 一致性）

**重入防护**：`FDraining` 标志；排水期间新产生的微任务追加到当前队列继续排空（同一轮），不递归进入。

## 4. Promise 与微任务

**值模型**：`TXuiJsPromise = class(TXuiJsObject)`（`JsClass='Promise'`）
- `State: (psPending, psFulfilled, psRejected)`、`Value: TXuiJsValue`
- `Reactions: TObjectList`（`TXuiJsReaction{OnFulfilled, OnRejected, Downstream, Kind}`）
- `Handled: Boolean`（未处理拒绝检测）

**方法**：`then/catch/finally` 挂 `PromiseProto`；静态 `resolve/reject/all/allSettled/race`。

**语义要点**
- 状态不可逆；settle 时把 reactions 逐个入队为**微任务**（保证回调永远异步）
- `then` 返回下游 Promise；回调返回值 resolve 下游，抛错 reject 下游；非函数参数透传
- `Promise.all` 任一 reject 即 reject；`allSettled` 收集 `{status, value|reason}`
- **未处理拒绝**：排水结束时扫描"已 reject 且未 attach 处理器"的集合 →
  经 `OnScriptError(stage=unhandledRejection)` 上报（v1 简化为每次排水检查一次）

## 5. async/await 实现（核心）

### ADR 16 —— 不做 regenerator 式 AST 降级，改把求值器做成**显式控制栈**（可挂起）

| 方案 | 评价 |
| --- | --- |
| A 编译期状态机降级（Babel/TS 的 `__generator`） | 需拆分表达式为临时变量、线性化控制流、维护临时值表；**语言语义会散落到"降级器 + 运行时"两处**，调试困难，代码量大 |
| **B 显式控制栈可挂起求值器（选定）** | 语义仍只有一处（求值器）；await 即"把控制栈从 Pascal 栈搬到堆上再返回"；try/catch/finally 与循环天然可表达；代价是求值器新增一套挂起路径 |

### 5.1 机制
- **语法树标记**：新增 `nkAwait` 节点与 `nfAsync` 标志；解析期自底向上传播 `HasAwait`（子树含 await）
- **快慢双路径**：`HasAwait = False` 的子树走**现有递归求值器**（零改动、零回归）；只有 await 主干走新求值器
- **帧栈**：`TXuiJsFrame{Node, Phase, 已求值操作数, Env, HandlerInfo}`，按"节点种类 × 相位"推进；
  离脊（不含 await）的操作数**委托现有求值器**同步算完，避免复制全部表达式逻辑
- **挂起**：遇 `nkAwait` → 求值被等待表达式 → 在 promise 上注册"恢复该帧栈"为微任务 → 退出切片（返回 promise 给调用方）
- **恢复**：微任务被泵执行 → 把结果压入帧栈 → 从相位继续
- **控制流**：`if/while/for/for..of` 在帧栈中保存条件重估点与迭代状态；`break/continue/return` 作为帧栈展开信号
- **异常**：帧栈记录 `try` 保护范围与 handler；展开时找最近 handler（已离开范围的不接），`finally` 作为独立帧执行
- **语义细节**：async 函数**同步执行到首个 await**；`this` 沿用现有环境机制（箭头词法 / 方法接收者）；
  `return await x` 解开一层再 resolve；async 递归自然支持
- **await 位置校验**（解析期）：非 async 函数内、模块顶层、`for await..of` → 中文报错并给出行列

### 5.2 风险与降级预案
- **最高风险**：`finally` 中含 await（挂起 + 多层展开交错）。若实现受阻 → **降级**：
  `try/catch` 内的 await 支持，但"含 await 的 `finally` 块"编译报错，写入不支持清单
- 次高风险：帧栈相位表完备性 → 用"全节点种类 × 每类至少一条 await 用例"的矩阵测试兜底

## 6. 定时器（宏任务）

### ADR 17 —— 定时器 = 引擎侧宏任务表 + Tick 泵

- 引擎侧表项 `{Id, Callback, DueMs, Interval, Cancelled}`；`Tick` 内取 `DueMs <= FClock` 执行
- 回调按**宏任务**执行：每个回调前重置预算、结束后排水微任务
- `ui.delay(ms): Promise` 基于定时器；`ui.now()` 取 `FClock`（测试可人造时间）
- `NeedsTick` 计入"定时器表非空"（宿主 Timer 已按需启停，无需改宿主）
- `setInterval` 固定间隔重排（不做漂移补偿）；`clearTimeout/clearInterval` 置 Cancelled 并回收

## 7. 真实 I/O

### ADR 18 —— I/O 走**工作线程 + 完成队列**，工作线程不接触 JS 值

**铁律（线程安全）**：工作线程只做系统调用，不持有、不创建、不触碰任何 JS 值；
跨线程只传"原始数据 + 状态码 + 请求 Id"，**所有 JS 值转换与 Promise settle 都在主线程安全点完成**。
（原因：解释器与 GC 均非线程安全，DOM 更是单线程。）

**接口**
```ts
ui.http.get(url, opts?): Promise<{status, headers, text(): string, json(): any}>
ui.http.post(url, body, opts?): Promise<Response>       // opts: {timeout?, headers?}
ui.fs.readText(path): Promise<string>
ui.fs.writeText(path, text): Promise<void>
ui.storage.get(key): string | null                       // 同步（内存 + 文件小对象）
ui.storage.set(key, value): void
```

**实现**
- HTTP：Windows 系统组件直声明（WinHTTP 或 WinInet，与既有 `gdiplus.dll` / `imm32.dll` 同做法，
  保持"零第三方依赖"）；请求在工作线程执行
- 文件：`TFileStream` 读写在**同一个 I/O 工作线程**串行执行（避免并发写冲突）
- 完成回传：工作线程写入**无锁完成队列**（单向），主线程在 Tick 轮询；
  `NeedsTick` 计入"在途请求数 > 0"
- **延迟**：完成回调最多等到下一个 Tick（宿主 Timer 16ms）→ 文档标注
  "异步完成延迟 ≤ 16ms；后续可用 PostMessage 唤醒降低"（不改接口）
- **超时与错误**：`opts.timeout` 超时 → reject 特定错误；网络/文件失败 → reject `Error`；
  均经 `OnScriptError(stage=io)` 记录但不中断应用
- **取消**：v1 不做；接口预留 `opts.signal`（传入即报"暂不支持"），内部为每个请求保留 Id/句柄以便后续接入

## 8. 预算 / GC / 错误

**预算（修现存缺陷）**
- 预算改为**按切片重置**：`Run`、`InvokeSlice`、每个微任务、每个宏任务进入时 `FSteps := 0`
- 挂起不累计（跨 await 的长期等待不会触发预算）
- 超预算：在何处切即在何处生效——若在 async 体内则 reject 该 promise，并 `OnScriptError(stage=budget)`

**GC 根扫描扩展**（在现有 `CollectGarbage` 标记集之外新增）
- 微任务队列（回调与参数）、宏任务队列（定时器回调、I/O 完成项）
- 活跃 async 帧栈（每个帧的环境、已求值操作数、所属 promise）
- 未处理拒绝表；在途 I/O 请求（原始数据非 JS 值，无需标记）
- 帧完成即从活跃表摘除（避免长链泄漏）

**错误分类**：编译期（语法/位置校验）· 运行时（同步抛出）· `unhandledRejection` · `io` · `budget`，
全部经 `OnScriptError` 上报，均不中断应用

## 11.1 后续修正（2026-09-13，M10 实现期间发现）

开发对话式 AI Agent（《M10-AI-Agent设计方案.md》）时，实测暴露本章 I/O 的三个既有缺陷，
均已修复并加回归测试：

| 缺陷 | 根因 | 影响 | 修复 |
| --- | --- | --- | --- |
| **HTTP 动词按加密状态选择** | `if secure then POST else GET` | https GET 发成 POST、http POST 发成 GET（静默错误） | 动词由 `iokHttpPost` 决定；TLS 只决定端口与 `WINHTTP_FLAG_SECURE` |
| **`opts.headers` 契约未实现** | `OptHeaders` 把 `opts` 顶层属性当请求头 | 文档写的 `{headers:{...}}` 里 `Content-Type`/`Authorization` 未发出，且 `headers`/`timeout` 被拼成垃圾头 | 优先取嵌套 `headers` 对象，排除 `timeout`/`signal` 选项键 |
| **页面脚本里 `ui.http` 为 undefined** | IO 由 `TXuiScript.IO` 懒安装；宿主/测试取 `.IO`，页面装配不取 | 页面 `<script>` 用 `ui.http/fs/storage` 都报"无法读取 undefined 的属性" | DOM 桥装配时主动 `FScript.IO` 一次 |

另新增 **`ui.time()`**：返回墙钟本地时间字符串。`ui.now()` 是会话相对毫秒（Tick 时钟），
表达不了"现在几点"，Agent 的时间工具需要真实时间戳。

## 13. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 可挂起求值器工作量大、相位表易漏 | 快慢双路径（无 await 子树零改动）+ 全节点矩阵测试；`finally` 内 await 可降级 |
| 排水时机不当破坏 DOM 一致性 | 安全点白名单（仅事件后 / Tick 内 / 加载后）+ 重入防护 + 禁止在布局绘制中途排水 |
| 跨线程事故 | 铁律：工作线程不接触 JS 值；跨线程只传原始数据 + 状态码；值转换全在主线程 |
| I/O 完成延迟（≤ 一个 Tick） | 文档标注；后续以 PostMessage 唤醒优化（不改接口） |
| 预算与长跑应用 | 切片化重置（同时修掉现存累积缺陷）；挂起不累计 |
| GC 漏根导致挂起帧被回收 | 根扫描显式包含微/宏任务队列与活跃帧；专项测试"挂起中对象存活" |
