# lui M9 设计方案：独立渲染程序（lui-render）

> 状态：设计待评审（2026-09-12）。基线：M8-3（runtests 633 项全绿）。
> 本文给出 `lui-render` 的定位、现状核查、问题清单、架构与分期方案。

---

## 1. 背景与现状（已核实）

**已存在原型但未固化**：上一阶段已产出可运行的渲染器雏形，但 `tools/`、`scripts/`、
`package.json` 全部**未纳入版本库**（`git status` 显示为未跟踪），且**无任何文档提及**
（`docs/` 检索 "lui-render/独立渲染器" 命中 0）。

**原型实测能力**（本轮逐一验证，非推测）：

| 项 | 实测结果 |
| --- | --- |
| 入口 | `tools/renderer/lui_render.lpr`（464 行）；工程 `lui_render.lpi`；产物 `bin/lui-render.exe` |
| 构建 | `lazbuild tools/renderer/lui_render.lpi` 通过（~2s，6228 行） |
| CLI 出图 | `lui-render <in.xml> --output out.png --width 560 --height 980 --theme light` —— 0.17s/页（组件库页，560×980） |
| 渲染质量 | GDI+ 抗锯齿；39KB PNG；SVG 矢量图标、圆角、渐变均正确 |
| 批量 | 7 个 demo 页（ui/m7/uidlg/uidisp/uinav/script/svg_demo）逐个出图，退出码均 0 |
| GUI 预览 | LCL 窗口 + F5 刷新 / T 切主题 / Esc 退出 |
| 主题 | 自动加载 `ui/theme/lui-light.css`（dark 再叠加 `lui-dark.css`） |
| 组件库 | 自动执行 `ui/index.ts`，**输入可用 `<ui-*>` 组件** |
| 样式发现 | 未指定 `-c` 时自动找 `<同名>-<theme>.css`、`<同名>.css`、`nav-<theme>.css` |
| `.svg` 输入 | 自动包一层全视口 `<window><svg src=.../></window>` |
| 退出码 | 0 成功 / 1 失败（输入缺失、XML 非法、输出不可写均正确返回 1） |
| 工程化 | `package.json` 定义 build/test/render/dev/clean；`scripts/build.js` 统一 lazbuild 三目标 |

**与 `demo1` 的关系**：`demo1` 是"演示应用"——为截图验收硬编码了各页交互模拟
（`demo/demo1.lpr` 的 `FBaseName = 'uidlg'` 等分支），只服务内置页面；`lui-render` 是
"通用工具"——任意输入 + 参数化。两者**装配逻辑高度重复**（`demo1.ApplyTheme` 与
`lui_render.SetupEngine` 各自实现"主题 + 组件库 + 关联 CSS 加载"）。

## 2. 目标与非目标

**目标**
- 通用 ：任意 `.xml` / `.svg` 输入，不依赖 demo 页面与硬编码交互
- CLI 优先：可脚本化批量出图、机器可读输出、退出码规范，可直接进 CI
- 交互预览：热重载（含依赖）、主题切换、缩放
- 复用引擎既有能力（依赖跟踪热重载、组件库、脚本引擎），不重复造轮子

**非目标（v1）**
- 非 Windows 的像素级一致：GDI+ 后端为 Windows 专属，其它平台降级 GDI（无抗锯齿）
- 无头/无显示服务器的跨平台保证（Windows 已可无头；Linux/macOS 需 headless widgetset 或 Xvfb，标为后续）
- PDF / SVG 矢量导出、动画序列/视频导出（后续按需）

## 3. 现状问题清单（实测确认）

| 编号 | 问题 | 证据 | 影响 |
| --- | --- | --- | --- |
| **P1** | `-h` 语义冲突：既是 `--help` 又是 `--height`（仅当它是最后一个参数时算 help） | `lui_render.lpr:78` 与 `:95` 两个分支都吃 `-h` | 用户 `lui-render a.xml -h 400` 意外出帮助/歧义；与 CLI 惯例（`-h`=help）冲突 |
| **P2** | 重载不重置样式表：`SetupEngine` 无 `ClearStyleSheets`，重载会**累积**样式表并重复执行 `ui/index.ts` | `lui_render.lpr:167-240`；对比 `demo1.ApplyTheme` 有 `ClearStyleSheets` | `--watch`、GUI 的 F5/T 主题切换越用越慢、样式重复叠加 |
| **P3** | 无批量模式：一次进程只处理一个输入 | `main` 单 `Opt.InputFile`；实测批量需循环调用 7 次（每次 ~0.17s + 启动） | CI 出全套图需外壳脚本；无法一次性报告汇总 |
| **P4** | 热重载只看输入文件自身，忽略依赖 | GUI `HandleWatchTimer` 仅 `FileAge(FInputFile)`（`:408-418`）；CLI watch 同（`:436-451`） | 改 CSS / `<include>` / `<script src>` 不触发重载；而引擎已具备 `RecordDocSources` + `ReloadChangedFiles`（`xui_engine.pas:349/387`） |
| **P5** | 缺 `--version` / 机器可读输出 | 无 | CI/脚本难判定版本与结果 |
| **P6** | 未知参数静默忽略 | `ParseCommandLine` 对无法识别的 `-x` 直接 `Inc(i)` 跳过 | 拼错参数不报错，静默按默认值出图 |
| **P7** | 输出目录不存在时报底层 OS 错误 | 实测 `-o /nonexistent/out.png` → `Unable to create file ... 系统找不到指定的路径` | 报错可用但不够友好；批量时易半途失败 |
| **P8** | 装配逻辑与 `demo1` 重复；CLI/GUI 混在单文件 | `SetupEngine` vs `ApplyTheme`；464 行单文件 | 双份维护，主题/组件库规则漂移风险 |
| **P9** | 无自动化测试 | 无 | 渲染器改动无回归防护 |
| **P10** | `.svg` 输入包窗口时硬编码白底、忽略 SVG 固有尺寸 | `lui_render.lpr:230-233` | 深色主题下 SVG 单独渲染仍是白底；未利用 viewBox 固有比例 |

## 4. 架构设计

### 4.1 运行模式（四态）

```
lui-render <input.xml|svg> [options]
  ├─ 单页导出   有 -o            → 渲染到一个 PNG
  ├─ 批量导出   --outdir / 多输入 → 每个输入一个 PNG（可 --theme both 出双份）
  ├─ 预览      （无 -o/--outdir） → LCL 窗口，交互查看
  └─ watch     任一模式 + --watch → 依赖变更后重跑（CLI 循环 / GUI 原地重载）
```

### 4.2 分层（消除 P8 重复）

```
src/ui/xui_app.pas（新建，引擎侧应用装配门面）
    TXuiApp = class
      procedure Configure(const AXmlFile, ATheme, AExtraCss: string;
                          AWidth, AHeight: Integer);   // 复位 + 装配
      property Engine / Script / Bridge / Host?
    —— 职责：ClearStyleSheets → 主题(light[+dark]) → ui/index.ts → 关联 CSS → 载入文档
    —— 供 lui-render 与 demo1 共用；集中 P2 的"复位"与样式发现规则

tools/renderer/lui_render.lpr      入口：CLI 解析 + 模式分派（薄）
tools/renderer/lui_render_cli.pas  批量/JSON/导出（可选拆分，控制单文件规模）
tools/renderer/lui_render_gui.pas  LCL 预览窗（可选拆分）
```

**收益**：装配规则一处维护；`demo1` 与 `lui-render` 行为一致；P2 在门面里根治。

### 4.3 CLI 规范（ADR 31，解决 P1/P5/P6）

| 选项 | 说明 |
| --- | --- |
| `-h, --help` | 帮助（**独占 `-h`**，不再兼任高度） |
| `-H, --height <px>` | 视口高度（大写 H；`--height` 为主用法） |
| `-w, --width <px>` | 视口宽度（默认 800×600） |
| `-o, --output <png>` | 单文件输出 |
| `-O, --outdir <dir>` | 批量输出目录（不存在则创建） |
| `-t, --theme light\|dark\|both` | 主题；`both` 各出一张（`<name>-light.png`/`-dark.png`） |
| `-c, --css <file>` | 附加样式（可多次） |
| `-s, --scale <1\|2>` | 导出倍率（HiDPI；v1 支持 1/2） |
| `--watch` | 依赖变更自动重跑（CLI 循环 / GUI 重载） |
| `--headless` | 强制无 GUI（CI 安全；GUI 模式下无效则忽略） |
| `--json` | 结果以 JSON 输出到 stdout（机器可读） |
| `--timeout <ms>` | 单页渲染上限（防挂死） |
| `-v, --verbose` | 过程日志 |
| `-V, --version` | 版本号 |
| `-?` | 帮助别名 |

**未知参数一律报错退出**（P6）；参数缺失给出中文提示 + 用法摘要。

### 4.4 退出码与错误（ADR 32，支撑 CI）

| 码 | 含义 |
| --- | --- |
| 0 | 全部成功 |
| 1 | 渲染/输入错误（XML 非法、文件缺失、输出不可写） |
| 2 | 参数错误（未知选项、缺值、非法枚举） |
| 3 | 批量部分失败（有成功也有失败；`--json` 给出逐项结果） |

错误信息走 stderr；`--json` 时 stdout 只含 JSON（日志走 stderr），保证可解析。

### 4.5 热重载（复用引擎，解决 P4）

- **CLI watch**：不用裸 `FileAge(input)`，改为周期性调用 `Engine.ReloadChangedFiles`
  （引擎已记录 XML/include/CSS 依赖的 FileAge 并在变化时就地重载），再重新导出。
- **GUI 预览**：直接启用引擎自带的 `FHotReload`（`Tick` 内节流轮询），删除自建 `TTimer`
  与 `FLastMTime`（`lui_render.lpr:337-344、408-418`）。
- 依赖变化即触发，覆盖 CSS / `<include>` / `<script src>`。

### 4.6 无头与 CI（ADR 33）

- **Windows（首选，已可用）**：`TBitmap` + GDI+ 全程无需显示服务器，`--headless` 即当前 CLI 路径。
- **Linux/macOS**：GDI+ 后端不可用 → 渲染降级 GDI（无抗锯齿）；且 LCL 需要 widgetset。
  v1 策略：明确"Windows 为像素级一等公民"；非 Windows 仅保证能构建 + GDI 出图，
  无头场景建议 Xvfb。真正跨平台清晰度需补一个后端（Cairo/fpvectorial），列为后续期，
  不在本方案承诺。

## 5. ADR（续 M8，编号 30 起）

| ADR | 决策 | 理由与代价 |
| --- | --- | --- |
| 30 | **lui-render 定位为通用工具**（参数化、无硬编码交互），与 `demo1`（内置演示 + 交互模拟）职责分离；二者共用装配门面 | 演示与工具各自演进、互不牵扯；代价：抽出 `xui_app` 需同步改造 `demo1` |
| 31 | **CLI 规范收敛**：`-h` 独占帮助、高度用 `-H/--height`；未知参数报错；加 `--version` | 与 GNU/主流 CLI 惯例一致、可组合进脚本；代价：与现有原型 `-h` 用法不兼容（原型未发布，无迁移负担） |
| 32 | **退出码分级 + `--json`**（0/1/2/3；错误走 stderr） | CI 可精确判定；代价：需在批量路径逐项收集结果 |
| 33 | **Windows-first 渲染清晰度；无头仅 Windows 保证**；跨平台后端为后续 | 零第三方依赖约束下，GDI+ 是唯一抗锯齿后端；代价：非 Windows 观感降级需文档明示 |
| 34 | **单程序分发 = 构建期资源内嵌 + 运行时解包到临时目录**（Base64 进 exe；首个运行按内容指纹解包，带就绪标记）；**不做内存 VFS**，保留"磁盘文件优先"的超集语义 | 引擎文件访问点十余处（XML/CSS/include/脚本 src/组件模板/SVG/热重载 FileAge），改 VFS 面大且会模糊热重载与 `ui.fs` 的真实 I/O 语义；解包复用全部既有能力，代价仅一次约 200KB 的解包 |
| 35 | **资源发现单一来源**：打包脚本不硬编码页面/样式清单，改调渲染器自身的 `--add-page` 得到每页关联资源 | 关联样式（`<同名>-<theme>.css`/`nav-*.css`）、`<include>`、`<script src>` 的解析规则与引擎同源，避免打包清单与运行时发现逻辑漂移 |

## 12. 实施记录（M9-P4：单程序分发，2026-09-13）

**目标**：`lui-render.exe` 之外再产出一个把脚本/xml/css 与 `ui/` 运行时资源全部内嵌的
单文件可执行程序（`bin/lui-render-single.exe`），拷走即可运行，无需携带外部资源。

### 12.1 机制（ADR 34/35）

```
构建期（scripts/embed.js）
  1. bin/lui-render.exe --add-page <页>    ← 让渲染器自己报每页的关联资源（ADR 35）
  2. 收集 ui/ 运行时 + 各页资源 + demo/assets → 排序拼接（可复现）
  3. 生成 tools/renderer/embedded/xui_embed_assets.pas
     （Base64 数据块分块常量 + 并列的资源名/大小数组 + 内容指纹）
  4. lazbuild lui_render_single.lpi（-dLUI_EMBED，独立 lib 目录 lib-single/）
  5. 冒烟：拷到系统临时目录（无 ui/、无 pages/）运行 --list-embedded 与出图
运行期（xui_embed.pas）
  XuiEmbedRoot → 按内容指纹解包到 %TEMP%\lui-embed-<指纹>（就绪标记，仅首次解包）
             → xui_app.FindRepoRoot 在磁盘查找失败后回落到该根目录
  XuiEmbedResolve → CLI 输入名在磁盘找不到时按 <根>/<名>、<根>/<pages>/<名> 解析
```

**超集语义**：磁盘上的同名文件始终优先。故同一个 exe 既能渲染内嵌演示页
（`lui-render-single.exe ui_gallery.xml -o out.png`），也能渲染任意外部 XML
（改动工作区文件立即生效，无需重新内嵌）；`--list-embedded` 可查看内嵌内容。

### 12.3 验证（实测）

- **空目录**（仅 exe，无 `ui/`、无 `pages/`）：`--list-embedded` 报 101 项；`ui_gallery.xml`
  / `login` / `uidlg` / `uinav` / `uidisp` / `ui` / `m7` / `todo` / `list` 全部出图成功；
  `-t dark` 正常；`-O out -t both` 批量出 4 张。
- **逐字节一致**：同为 `ui_gallery.xml 460×720 light`，磁盘版与单程序版 PNG 的 MD5 相同
  （`3c27e9a1…`），证明内嵌解包与直接读文件渲染结果一致。
- **超集语义**：空目录内放一个外部 `ext.xml`，同一 exe 正常渲染该外部文件。
- **回归**：`npm test` 633 项全绿；`demo1` 改用门面后仍正常构建与出图。
- **规模**：内嵌 101 个文件 / 196.7 KB（指纹 `980009e6…`），exe 约 28.0 MB。

### 12.4 已知限制

- 内嵌输入名不含 `..` 片段（`../ui/index.ts` 一类仍由内嵌的 `ui/` 目录满足，不需要也不
  应作为命令行输入）；磁盘上存在同名文件时一律以磁盘为准（调试便利优先于"纯内嵌"）。
- 首帧有一次性解包开销（约 200KB，实测可忽略）；解包目录按内容指纹缓存，改资源即换目录。
- 仅 `lui-render` 有单程序版；`demo1`（演示应用，硬编码交互）仍按 `npm run pack` 的目录
  形态分发。
