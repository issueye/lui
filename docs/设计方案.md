# lui — FPC 自绘界面引擎 设计方案（v1.0 定稿）

> **lui**（Lightweight UI）：用 Free Pascal/Lazarus 开发、以 **XML 描述结构 + CSS 子集描述样式**
> 的自绘界面引擎——不使用原生 Win 控件，由引擎自己在一块画布上完成布局与绘制，思路对标 LCUI。
>
> 状态：方案已评审定稿（2026-09-11），四个关键决策已确认，见 §6 ADR。

---

## 1. 需求

### 1.1 功能需求

| # | 需求 | 说明 |
| --- | --- | --- |
| F1 | XML 界面描述 | 用 XML 声明元素树（panel/label/button/image…），运行时加载构建 |
| F2 | CSS 样式描述 | 用 CSS 子集声明外观与布局，支持选择器、级联、继承 |
| F3 | 自绘渲染 | 所有元素由引擎绘制（背景/边框/文字/图片），不依赖 LCL 可视控件 |
| F4 | 盒模型 + Flex 布局 | margin/padding/border 盒模型；flex 纵横布局、对齐、间距 |
| F5 | 交互 | hover/active/focus/disabled 伪类；点击等事件回调到 Pascal 代码 |
| F6 | 动态性 | 运行时可改类名/样式并触发重排重绘；（后期）热重载 |
| F7 | 集成性 | 作为一个控件（TXuiHost）嵌入任意 Lazarus 窗体，可被 aluka_chat 等项目使用 |

### 1.2 非功能需求

- N1 零第三方依赖（仅 RTL + LCL/LazUtils + Windows 系统组件 gdiplus.dll）
- N2 单窗口界面重排+重绘 ≤ 8ms（60fps 预算内）
- N3 引擎核心（解析/样式/布局）与平台渲染解耦，渲染后端可替换
- N4 中文/中英混排正确换行，行高、字号可控

### 1.3 非目标（v1 明确不做）

- 不做 HTML，不做完整 CSS3（动画/变换/网格布局后续按需加）
- 不做浏览器级文字 shaping（连字/复杂文种）；IME 输入框放 M5 独立处理
- v1 仅 Windows；渲染后端留接口，跨平台后置

## 2. 总体架构

```
┌─────────────────────────────────────────────────────────────┐
│                      宿主 Lazarus 应用                        │
│   TForm ── TXuiHost(TCustomControl)  ← 唯一的原生控件入口      │
└─────────────────────────────────────────────────────────────┘
                 │ 鼠标/键盘/绘制/尺寸变化
┌────────────────▼────────────────────────────────────────────┐
│ xui_engine  引擎门面：加载 → 构建文档 → 样式 → 布局 → 渲染      │
│                                                              │
│  ┌──────────┐  ┌──────────────┐  ┌────────────────────────┐ │
│  │ xui_xml  │  │ xui_css_*    │  │ xui_widget  元素/工厂    │ │
│  │ XML→节点树│  │ 词法/解析/匹配 │  │ (button,label,image...) │ │
│  └────┬─────┘  └──────┬───────┘  └───────────┬────────────┘ │
│       ▼               ▼ 计算样式               ▼              │
│  ┌──────────────────────────────┐  ┌────────────────────────┐ │
│  │ xui_dom  节点树 + xui_style   │  │ xui_events 命中测试/分发 │ │
│  │          计算样式结构          │  └────────────────────────┘ │
│  └──────────────┬───────────────┘                              │
│                 ▼                                              │
│  ┌──────────────────────────────┐  ┌────────────────────────┐ │
│  │ xui_layout 盒模型/flex/文本   │  │ xui_render 渲染接口      │ │
│  │          布局引擎             │  │  ├ TGdiRenderer (M1)    │ │
│  └──────────────────────────────┘  │  └ TGdiPlusRenderer(M4) │ │
│                                    └────────────────────────┘ │
└──────────────────────────────────────────────────────────────┘
```

数据流（一次刷新）：
`XML 文件 + CSS 文件 → 节点树 → 匹配/级联 → 每节点 ComputedStyle → 布局计算出矩形 → 渲染器绘制`
运行期：输入事件 → 命中测试 → 伪类变化/事件回调 → 标脏（样式/布局/绘制）→ 增量刷新。

## 3. 界面描述语言设计

### 3.1 XML 示例（登录卡片，即 M1 验收 demo）

```xml
<window title="登录" width="360" height="220">
  <panel id="login-card" class="card">
    <label class="title" text="登录 Aluka"/>
    <panel class="row">
      <label class="field-label" text="用户名"/>
      <input id="username" class="textbox"/>
    </panel>
    <panel class="row">
      <label class="field-label" text="密码"/>
      <input id="password" class="textbox" password="true"/>
    </panel>
    <button id="btn-ok" class="primary-btn" text="登 录" onclick="BtnOkClick"/>
    <label id="msg" class="error-label"/>
  </panel>
</window>
```

要点：
- 标签名 = 元素类型，由**元素工厂**注册（可扩展自定义元素）
- `id` / `class` 与 CSS 对应；业务属性（`text`、`password` 等）由各元素行为解释
- `onclick="方法名"` 通过 RTTI 绑定到宿主对象的 published 方法（类似 DFM 事件心智）
- 文本内容与 `text` 属性二选一，文本子节点合并为该元素的文本

### 3.2 CSS 示例

```css
/* 类型选择器 */
label { font-size: 14px; color: #333333; }

/* class 选择器 */
.card {
  display: flex; flex-direction: column; gap: 10px;
  width: 320px; padding: 20px; margin: 10px auto;
  background-color: #ffffff;
  border: 1px solid #e0e0e0; border-radius: 8px;  /* 圆角需 M4 GDI+ 后端 */
}
.card .title { font-size: 20px; font-weight: bold; color: #1a1a1a; }
.row { display: flex; flex-direction: row; align-items: center; gap: 8px; }

/* id 选择器 + 伪类 */
#btn-ok { height: 36px; background-color: #4a7df0; color: #ffffff; }
#btn-ok:hover    { background-color: #3a6de0; }
#btn-ok:active   { background-color: #2a5dc0; }
#btn-ok:disabled { background-color: #a0a0a0; }

.error-label { color: #e02020; font-size: 12px; display: none; }
```

## 4. CSS 子集规范（v1 白名单）

**选择器**：类型（`label`）、`#id`、`.class`、`*`、后代（空格）、子代（`>`）、
伪类 `:hover :active :focus :disabled`；特异性 `(id, class+伪类, 类型)` 三元组比较，同值后者优先；
支持 `style=""` 内联（仅次于 `!important`）与 `!important`。

**属性表（v1 支持）**：

| 分组 | 属性 |
| --- | --- |
| 显示 | `display`(block/flex/none)、`position`(static/relative/absolute)、`z-index`(有限支持) |
| 定位偏移 | `top right bottom left`（auto/px/%；绝对与相对定位共用） |
| 盒模型 | `width height min-width min-height margin* padding* border* box-sizing`(content-box/border-box) |
| Flex | `flex-direction`(row/column)、`justify-content`(flex-start/center/flex-end/space-between/space-around)、`align-items`(flex-start/center/flex-end/stretch)、`gap row-gap column-gap`、`flex-grow flex-basis flex`(简写 = grow + basis:0) |
| 背景 | `background-color`；`background-image`(v2 渐变) |
| 文字 | `color font-family font-size font-weight text-align line-height letter-spacing` |
| 圆角/透明 | `border-radius`(单值 px；GDI 近似、GDI+ 抗锯齿)、`opacity`(0..1，alpha 连乘近似) |
| 过渡（M5） | `transition`(属性列表/`all` + 时长 + 时间函数 + 延迟；仅绘制类属性，单条规格) |
| 其他 | `overflow`(visible/hidden，hidden 同时是滚动容器)、`visibility`(visible/hidden) |

单位：`px`、`%`、`em`（相对父字号）；颜色：`#rgb #rrggbb rgba() rgb()` 及常用命名色。

## 5. 核心模块设计

### 5.1 文档模型（xui_dom / xui_style）

```pascal
TXuiNode = class
  Tag, Id: string; Classes: TStringList; Attributes: TStrings; Text: string;
  Parent, FirstChild...: TXuiNode;           // 树
  Style: TXuiComputedStyle;                   // 级联计算结果
  Pseudo: TXuiPseudoStates;                   // hover/active/focus/disabled
  Frame: TXuiFrame;                           // 布局结果 margin-box/content-box 矩形
  Behavior: TXuiBehavior;                     // 元素行为(可空)
end;
```

样式脏标记三级：`StyleDirty → LayoutDirty → PaintDirty`，按需向上/向下传播。

### 5.2 CSS 引擎（xui_css_token / parser / match）

- 手写词法分析器 + 递归下降解析（FCL 无现成 CSS 解析器）→ `TRule(选择器组, 声明表)`
- 匹配：自根向叶遍历树，对每节点收集命中规则 → 按特异性排序合并 → 继承（color/font 类属性）
- 值解析即时完成：长度/颜色/关键字解析为强类型值，避免每帧重复解析字符串

### 5.3 布局引擎（xui_layout）

- 盒模型：content/padding/border/margin，默认 `border-box`（可配置）
- 排版上下文：块级（纵向堆叠）+ **flex 子集**：`row/column + justify/align + gap + grow`；
  不做 wrap/负 margin/基线对齐（列出不支持清单防蔓延）
- 文本排版（xui_text）：按词断行 + CJK 逐字断行；系统 API 测量字宽；`line-height`、`text-align`
- 绝对定位：相对最近的非 static 祖先

### 5.4 渲染（xui_render）

```pascal
IXuiRenderer = interface
  procedure FillRect(const R: TRect; AColor: TXuiColor);
  procedure DrawBorder(...);                    // M1 固定 0 圆角
  procedure DrawText(...);  MeasureText(...): TSize;
  procedure DrawImage(...);
  procedure PushClip/PopClip;                   // overflow:hidden 裁剪
end;
```

- **M1：TGdiRenderer** —— 包一层 LCL `TCanvas`（GDI），零依赖，直角无抗锯齿
- **M4：TGdiPlusRenderer** —— 直接 `external 'gdiplus.dll'` 声明所需 ~30 个扁平 API，
  获得抗锯齿圆角、半透明、渐变；GDI+ 是 Windows 系统组件，仍算零第三方依赖
- 宿主 `TXuiHost = class(TCustomControl)`：DoubleBuffered、OnPaint→引擎绘制、
  OnMouse* → 事件系统、WM_SIZE → 全量重排、InvalidateRect 脏区刷新

### 5.5 元素与行为（xui_widget）

- 样式绘制由引擎按 ComputedStyle 统一完成；**行为类**只加交互：
  `TLabelBehavior(text)`、`TButtonBehavior(click/伪类/Enter 激活)`、`TInputBehavior`(M5：编辑/光标/选区/掩码/占位符)、
  `TImageBehavior`、`TScrollBehavior`(M4)
- 工厂：`RegisterElement('button', TButtonBehavior)`，XML 未知标签回退为 panel + 告警

### 5.6 事件系统（xui_events）

- 命中测试：按逆 Z 序递归找最深层可见节点（尊重 overflow 裁剪）
- 伪类状态机：mousemove 维护 hover 链；mousedown/up 维护 active；点击 = 同节点 down+up
- 绑定：XML `onclick="BtnOkClick"` → 宿主 published 方法（`MethodAddress`，与 DFM 同机制）；
  另有 `OnEvent` 兜底统一处理（适合动态界面）。M5 新增 `oninput` / `onenter` / `onmousemove` 绑定；
  原始 `onkeydown/onkeyup` 不提供绑定（`TNotifyEvent` 无按键载荷），键盘交由行为类解释
- 键盘（M5）：宿主覆写 `KeyDown/KeyUp/UTF8KeyPress` → 引擎沿焦点链派发；
  `Tab/Shift+Tab` 焦点遍历、`Enter` 在按钮上等价点击（M4 遗留项闭合）；
  文本输入（含 IME 上屏）走 `xevTextInput`，UTF-8 一次可多字符
- 指针捕捉（M5）：行为声明 `NeedsPointerCapture` 后，mousemove/mouseup 优先派发给该节点（输入框拖选）

## 6. 关键决策（ADR，已确认 2026-09-11）

| ADR | 决策 | 理由与代价 |
| --- | --- | --- |
| 1 渲染后端 ✅ | 接口 `IXuiRenderer` 隔离；**M1 用 LCL Canvas(GDI)，M4 增 GDI+ 后端** | 零依赖快速见效；代价是 M1-M3 无抗锯齿圆角。备选：Direct2D（COM 绑定成本高）、OpenGL（上下文/跨平台复杂）已否决 |
| 2 布局模型 ✅ | **盒模型 + flexbox 子集**，不做完整 CSS2.1 行内流 | LCUI 路线已被验证够用；完整流式布局工作量数倍且难调试 |
| 3 控件模型 ✅ | 节点（样式+布局）与行为（交互）分离，轻量工厂创建 | 避免重造一套 LCL 控件体系；行为可组合 |
| 4 事件绑定 ✅ | XML 属性名 → RTTI 绑定宿主 published 方法 + 引擎级兜底事件；**M6 起可回退到脚本全局函数** | 与 Lazarus/DFM 心智一致、零脚本依赖；脚本引擎已于 M6 落地（TypeScript 子集，纯 Pascal 自研） |
| 5 XML 解析 ✅ | laz2_XMLRead/laz2_DOM（LazUtils 自带） | 零依赖、成熟稳定 |
| 6 工程形态 ✅ | 独立工程 `fpc_projects\lui`；units + demo，不打包 .lpk | aluka_chat 等引用时加搜索路径即可；后期需要再补包 |
| 7 落地路线 ✅ | **先做独立 Demo（登录卡片 → 计算/Todo）验证引擎，再迁移 aluka_chat 界面** | 降低两线作战风险 |
| 8 文本输入/IME ✅ M5 | 引擎自持编辑模型（值即 `Node.Text`），宿主覆写 `KeyDown/UTF8KeyPress` 转文本输入；<br>IME 走 **MVP：`WM_IME_*` 定位系统组合窗到引擎光标（imm32），上屏文本经 `UTF8KeyPress` 插入** | 不自绘组合串、不做内联 preedit（复杂度高、收益低）；代价是组合串样式跟随系统输入法 |
| 9 过渡动画 ✅ M5 | 样式新增 `transition`（白名单：opacity/颜色/圆角）；引擎在**样式重算前后快照→diff** 启动插值，时间由宿主 `Tick` 注入 | 只动画绘制类属性、不触发布局（代价：不能过渡尺寸/位置）；纯逻辑单元便于测试 |
| 10 模板复用 ✅ M5 | `<include src>` 在 **XML 解析期展开**（`<template>` 根展开为多节点，否则展开根元素） | 下游（样式/行为/布局）零改动；代价：不支持带参数模板与条件包含 |
| 11 热重载 ✅ M5 | 记录 XML/样式表来源与 FileAge；Tick 节流轮询：**仅 CSS 变化就地重解析（保留 DOM），XML/include 变化重建文档** | 日常改样式不丢运行时状态；改结构需重建（运行时改动不保留），已写入不支持清单 |

### M1 完成记录（2026-09-11）

- 交付单元：xui_types / xui_style / xui_dom / xui_xml / xui_render / xui_layout / xui_widget / xui_engine / xui_host
- 测试：tests/runtests（控制台自校验）25 项全部通过（XML 解析 / 默认样式 / 块级布局）
- 验收：demo1 实机运行，登录卡片（标题/两组输入框/按钮/说明文案）完全由引擎自绘
- 过程中修复：构造顺序 bug（`Width := 320` 触发 Resize 时 FEngine 尚未创建，已加 nil 防护）；
  text 属性未落入节点文本（加载器补齐）；布局器对未计算样式节点直接崩溃（EnsureStyles 兜底）
- 已知边界：文本单行绘制（垂直居中）；块级流布局；auto 外边距按 0；百分比高度以视口为参照；
  这些都在 M2/M3 计划内

### M2 完成记录（2026-09-11）

- 交付单元：xui_css_token（词法）/ xui_css_parser（解析+特异性）/ xui_css_match（匹配+级联+值应用）
- 能力：类型/#id/.class/*/后代/子代选择器；:hover :active :focus :disabled 伪类匹配；
  特异性三元组级联 + 源顺序；内联 style 介于普通规则与 !important 之间；继承走默认样式链；
  颜色（#hex/rgb()/rgba()/命名/transparent）、长度（px/%/em/auto）、margin/padding 1-4 值简写、
  border 简写、font-size（em/%）、font-weight、text-align、line-height（倍数/px/%）
- 测试：runtests 扩至 41 项全绿（新增解析/简写/级联/内联/换肤用例）
- 验收：demo1 同一份 login.xml 点击切换 login-light.css / login-dark.css 双主题（也支持 `demo1 dark` 启动参数）
- 过程中修复的关键 bug：
  1. 词法器吞掉空白导致后代组合器失效 → 空白折叠为独立 token，解析器以空白判定后代组合器
  2. `#name` 为单 token（名字在 token 文本内），解析器误以为 "#" 后跟独立 ident
  3. 声明循环中空白落入 else 分支多吃下一个 token（属性名凭空消失）→ 补 ctkWhitespace/ctkColon 分支
  4. 颜色 hash token 拼值时丢失 `#`（#ff0000 → ff0000 解析成黑色）→ 值拼接时补回 `#`
  5. 残片选择器双重释放（失败路径与 finally 各释放一次）→ 统一由 finally 释放
- 已知边界：em 基准随应用顺序取当前字号（非常规用法下有偏差）

### M3 完成记录（2026-09-11）

- 交付单元：xui_text（新建）、xui_layout（重写）、xui_dom / xui_style / xui_types / xui_css_match /
  xui_render / xui_engine / xui_host（扩展）
- 能力：
  - **flex 子集**：`flex-direction` row/column；主轴 `flex-basis > width/height > max-content` 推导 +

## 8. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 文字排版（中英混排换行、测量性能） | 用系统 GDI 测量；缓存测量结果；复杂 shaping 明确不做 |
| CSS 特性蔓延 | 白名单 + 每里程碑冻结属性表；文档维护"不支持清单" |
| 全量重排性能 | v1 全量重绘 + DoubleBuffer 兜底；预留脏区/增量重排接口 |
| GDI 阶段观感差（无 AA） | 设定预期：M4 上 GDI+ 后一次性补齐；demo 样式规避圆角 |
| IME/输入框复杂度 | ✅ M5 已按 MVP 落地（系统组合窗 + UTF8KeyPress 上屏），内联组合串明确不做 |
| 过渡动画与布局耦合 | 只白名单绘制类属性；插值写回样式但不置布局脏，避免每帧重排 |
